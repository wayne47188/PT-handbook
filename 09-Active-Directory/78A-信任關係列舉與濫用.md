## 學習目標

- 理解五種 AD 信任類型的定義與攻擊意涵。
- 用 Get-ADTrust / Get-DomainTrust / netdom query 完整列舉信任關係。
- 用 Get-DomainTrustMapping 遞迴對應整個信任拓樸。
- 用 Get-DomainUser -Domain 對受信任網域執行跨網域列舉。

## 理論基礎

```text
信任關係攻擊意涵
  → 信任關係常設定不當 → 提供非預期攻擊路徑
  → 常見情境：
      → M&A（企業併購）建立雙向信任 → 被收購公司防護較弱 → 間接入侵主網域
      → 跨信任 Kerberoast → 取得主網域內具管理權限的使用者帳號
      → 較大組織不知道與哪些網域存在信任關係（未文件化）

信任類型一覽：
  ┌──────────────────────────────────────────────────────────────────┐
  │ 類型           │ 說明                                            │
  ├──────────────────────────────────────────────────────────────────┤
  │ Parent-child   │ 同一樹系內的父子網域，自動雙向遞移信任           │
  │ Cross-link     │ 同一樹系內不同樹之間的捷徑信任，縮短驗證路徑     │
  │ External       │ 與另一樹系的特定網域建立信任（非遞移）           │
  │ Tree-root      │ 在同一樹系內新增樹根網域時自動建立               │
  │ Forest         │ 與另一樹系整體建立信任（可選擇遞移）             │
  └──────────────────────────────────────────────────────────────────┘

信任方向：
  → 雙向（Bidirectional）→ 兩個網域均可驗證對方的使用者
  → 單向（Unidirectional）→ 只有信任網域（Trusting）的使用者可存取被信任網域（Trusted）
  → 雙向信任 = 兩個方向皆可攻擊

Inlanefreight 實驗環境信任拓樸：
  → Inlanefreight.LOCAL ←→ freightlogistics.LOCAL（Tree-root，雙向）
  → Inlanefreight.LOCAL ←→ LOGISTICS.INLANEFREIGHT.LOCAL（Parent-child，雙向）
  → LOGISTICS ←→ corp.Inlanefreight（Parent-child，雙向）
  → corp.Inlanefreight ←→ wh.corp.Inlanefreight（Parent-child，雙向）
  → wh.corp ←→ admin.dev.Inlanefreight（Cross-link，雙向）
  → freightlogistics → shippinglanes（Forest，雙向）
  → dev.Inlanefreight → shippinglanes（External，單向）
```

## 一、Get-ADTrust（RSAT 內建）

### 理論

```text
Get-ADTrust — Active Directory PowerShell 模組原生 cmdlet
  → 不依賴 PowerView → 在無第三方工具環境中仍可使用
  → -Filter * → 列舉所有信任關係

關鍵欄位判讀：
  IntraForest = True          → 同一樹系內的信任（子網域、Tree-root）
  IntraForest = False         → 跨樹系信任（External / Forest）
  ForestTransitive = True     → Forest 信任（跨整個樹系）
  ForestTransitive = False    → External 信任（指向特定網域）
  Direction = BiDirectional   → 雙向 → 可往兩個方向攻擊
  Direction = Inbound/Outbound → 單向 → 確認攻擊方向
  SIDFilteringQuarantined     → SID 過濾是否啟用（Forest 信任的安全機制）
  SelectiveAuthentication     → 是否啟用選擇性驗證（限制跨信任驗證範圍）
  TGTDelegation = False       → TGT 不可委派（預設，攻擊受限）
```

```powershell
# 匯入 AD 模組（若未載入）
Import-Module activedirectory

# 列舉所有信任關係
Get-ADTrust -Filter *

# 關鍵欄位範例輸出：
# Direction               : BiDirectional
# IntraForest             : True          → 子網域（LOGISTICS.INLANEFREIGHT.LOCAL）
# ForestTransitive        : False         → 非 Forest 信任
# SIDFilteringQuarantined : False         → SID 過濾未啟用 → SID History 攻擊可行
# TGTDelegation           : False         → TGT 不可委派（需其他攻擊路徑）
#
# Direction               : BiDirectional
# IntraForest             : False         → 跨樹系
# ForestTransitive        : True          → Forest 信任（FREIGHTLOGISTICS.LOCAL）
# SIDFilteringQuarantined : False         → SID 過濾未啟用 → ExtraSids 攻擊可行
```

## 二、Get-DomainTrust（PowerView）

### 理論

```text
Get-DomainTrust — PowerView 版本
  → 輸出更精簡，適合快速判讀
  → TrustAttributes 直接顯示語意（WITHIN_FOREST / FOREST_TRANSITIVE）
  → 適合在有 PowerView 的環境替代 RSAT

TrustAttributes 值：
  WITHIN_FOREST    → Parent-child 或 Tree-root（同樹系內）
  FOREST_TRANSITIVE → Forest 信任（跨樹系）
  QUARANTINED_DOMAIN → SID 過濾已啟用
```

```powershell
# 列舉當前網域的信任關係（PowerView）
Get-DomainTrust

# 輸出欄位：
# SourceName     : INLANEFREIGHT.LOCAL         → 當前網域
# TargetName     : LOGISTICS.INLANEFREIGHT.LOCAL → 被信任網域
# TrustType      : WINDOWS_ACTIVE_DIRECTORY
# TrustAttributes: WITHIN_FOREST              → 同樹系內信任
# TrustDirection : Bidirectional              → 雙向

# SourceName     : INLANEFREIGHT.LOCAL
# TargetName     : FREIGHTLOGISTICS.LOCAL
# TrustAttributes: FOREST_TRANSITIVE          → 跨樹系 Forest 信任
# TrustDirection : Bidirectional              → 雙向
```

## 三、Get-DomainTrustMapping（PowerView 完整對應）

### 理論

```text
Get-DomainTrustMapping — 遞迴列舉所有可達網域的信任關係
  → 不只看目前網域 → 繼續對每個受信任網域查詢信任
  → 建立完整信任拓樸地圖（用於規劃攻擊路徑）

用途：
  → 確認整個環境的信任邊界
  → 找出通往目標網域的信任鏈
  → 識別未預期的信任（常見於 M&A 環境）
```

```powershell
# 遞迴對應所有信任關係
Get-DomainTrustMapping

# 輸出包含：
# INLANEFREIGHT.LOCAL → LOGISTICS.INLANEFREIGHT.LOCAL（Bidirectional）
# INLANEFREIGHT.LOCAL → FREIGHTLOGISTICS.LOCAL（Bidirectional）
# FREIGHTLOGISTICS.LOCAL → INLANEFREIGHT.LOCAL（Bidirectional）← 反向也顯示
# LOGISTICS.INLANEFREIGHT.LOCAL → INLANEFREIGHT.LOCAL（反向）

# 分析：形成完整圖 → 規劃跨域攻擊路徑
```

## 四、跨網域使用者列舉

### 理論

```text
確認可以向信任網域列舉後 → 開始跨域列舉使用者
  → 用途：找出高權限帳號、可 Kerberoast 的 SPN 帳號
  → 前提：信任方向允許（Bidirectional 或 Outbound 至目標）

重點帳號：
  → krbtgt → 確認是每個網域獨立的（Golden Ticket 僅對本網域有效）
  → DA 帳號 → 確認是否有在多個網域共用帳號
  → SPN 帳號 → 跨域 Kerberoasting 目標
```

```powershell
# 列舉子網域（LOGISTICS）使用者
Get-DomainUser -Domain LOGISTICS.INLANEFREIGHT.LOCAL |
  Select-Object SamAccountName

# 輸出：
# samaccountname
# htb-student_adm
# Administrator
# Guest
# lab_adm
# krbtgt

# 進一步：對子網域執行 Kerberoasting
Get-DomainUser -Domain LOGISTICS.INLANEFREIGHT.LOCAL -SPN |
  Select-Object SamAccountName, ServicePrincipalName

# 跨域 BloodHound 資料收集（從當前網域蒐集目標網域資訊）
# → 在 BloodHound GUI 使用 "Map Domain Trusts" 預建查詢
```

## 五、netdom 查詢（CMD 原生工具）

### 理論

```text
netdom query — Windows 原生工具，不需 PowerShell / RSAT
  → 適用於受限環境（CLM 模式 / AppLocker 封鎖 PS）
  → 可查詢：信任關係 / DC / 工作站與伺服器

子命令：
  netdom query /domain:DOMAIN trust       → 列出信任關係
  netdom query /domain:DOMAIN dc          → 列出網域控制站
  netdom query /domain:DOMAIN workstation → 列出工作站與伺服器
```

```cmd
REM 查詢信任關係
netdom query /domain:inlanefreight.local trust
REM 輸出：
REM <-> LOGISTICS.INLANEFREIGHT.LOCAL   Direct
REM <-> FREIGHTLOGISTICS.LOCAL          Direct

REM 查詢網域控制站
netdom query /domain:inlanefreight.local dc
REM 輸出：
REM ACADEMY-EA-DC01

REM 查詢工作站與伺服器（被管主機清單）
netdom query /domain:inlanefreight.local workstation
REM 輸出：ACADEMY-EA-MS01, SQL01, ILF-XRG...
REM → 用於建立目標主機清單
```

## 判斷邏輯

```
取得網域據點 → 列舉信任關係
│
├── 工具選擇
│   ├── 有 RSAT → Get-ADTrust -Filter *
│   ├── 有 PowerView → Get-DomainTrust
│   ├── 只有 CMD → netdom query /domain:DOMAIN trust
│   └── 完整對應 → Get-DomainTrustMapping（PowerView）
│
├── 分析信任欄位
│   ├── IntraForest = True → 子網域 → 可能繼承父網域信任
│   ├── ForestTransitive = True → Forest 信任 → 全樹系可達
│   ├── Direction = Bidirectional → 雙向 → 可跨域列舉與攻擊
│   └── SIDFilteringQuarantined = False → SID History / ExtraSids 攻擊可行
│
├── 跨域列舉
│   ├── Get-DomainUser -Domain TARGET → 找高權限帳號 / SPN 帳號
│   ├── Get-DomainUser -Domain TARGET -SPN → 跨域 Kerberoasting 目標
│   └── BloodHound "Map Domain Trusts" → 視覺化完整信任拓樸
│
└── 攻擊路徑研判
    ├── 子網域 DA → SID History 攻擊 → 父網域 DA（見持久化章節）
    ├── 跨樹系 Kerberoast → 取得跨域高權限帳號
    └── 被收購公司網域 → 防護較弱 → 迂迴進入主網域
```

## 信任類型速查

```
Parent-child  → 同樹系，自動雙向遞移 → 子域 DA → SID History → 父域 DA
Tree-root     → 同樹系，樹根信任
Cross-link    → 同樹系，捷徑（縮短 Kerberos 驗證路徑）
External      → 跨樹系，指定網域，非遞移 → SID 過濾通常啟用
Forest        → 跨樹系整體，可選擇遞移 → SID 過濾預設啟用（但常未啟用）
```
