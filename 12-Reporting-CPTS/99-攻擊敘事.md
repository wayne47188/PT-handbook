# 第 99 章 - 攻擊敘事

## 標籤

- #cpts
- #chapter
- #reporting
- #narrative

## 學習目標

- 理解 attack narrative 與單一 finding 清單的差異。
- 能將多個低/中風險發現串成高價值攻擊路徑。
- 知道如何清楚描述前提、轉折、依賴與最終影響。
- 讓讀者理解「風險為何大於各 finding 單獨相加」。
- 避免把 narrative 寫成誇張故事或無證據推演。

---

## 理論基礎

```text
Attack Narrative 的核心問題：

不是「我發現了哪些 finding」
而是「這些 finding 如何被串接成一條攻擊者實際會走的路徑」

Finding 清單 vs Attack Narrative 的差異：

  Finding 清單（不夠）：
    Finding 1: 密碼重用（Medium）
    Finding 2: SMB 橫向移動（High）
    Finding 3: GPO 設定不當（High）
    
    → 決策者看到 3 條獨立問題，可能各自排序
    → 無法理解「這三個問題組合在一起有多危險」

  Attack Narrative（有力）：
    一名低權限網域帳號因密碼重用被驗證（Finding 1）
    → 該帳號可存取財務部門工作站（Finding 2 的前提）
    → 工作站上有高權 session，且 GPO 路徑可控（Finding 3）
    → 攻擊者可從外圍低權帳號直達網域管理員
    
    → 決策者理解：這不是三個問題，而是一條攻擊鏈
    → 切斷任一環節都能阻斷整條路徑

Narrative 的價值在於說明控制鏈的存在：
  → 攻擊者自然沿著路徑行動，不把 finding 分章節看
  → 防禦者需要 narrative 才能判斷「應優先切斷哪一環」
```

## Narrative 結構框架

```text
Attack Chain 的標準組件：

1. Initial Access（初始入口）
   → 攻擊者如何進入：外部服務漏洞、憑證、社交工程
   → 必須標明：是否需要認證？是否需要使用者互動？

2. Credential / Service Abuse（憑證或服務濫用）
   → 利用取得的存取進行橫向探索
   → 包含：密碼重用、Hash 傳遞、Kerberoasting

3. Lateral Movement（橫向移動）
   → 從初始主機擴展到高價值目標
   → 依賴：網路可達性 + 憑證有效性 + 服務配置

4. Privilege Escalation（提權）
   → 從低權移動到高權（本機 root 或網域管理員）
   → 依賴：特定設定弱點（sudo/cron/ACL/AD CS）

5. Domain / System Impact（最終影響）
   → 攻擊者能在此位置做什麼
   → 技術影響（全網域控制）→ 業務影響（完整資料存取）

每一步的必填資訊：
  → 依賴的 finding 編號（可回溯到具體證據）
  → 前提條件（這一步成立的必要條件）
  → 轉折（若無此弱點，攻擊者在哪裡被阻斷）
```

## Narrative 撰寫品質對比

```text
# ===== 低品質 Narrative（不可接受）=====

描述：攻擊者可以進入系統，然後取得更高權限，
      最後可能存取所有資料，威脅很大。

問題：
  → 沒有具體 finding 支撐（推測性路徑）
  → 跳過關鍵步驟與前提
  → 故事性太強、證據性太弱
  → 讀者無法從此敘述決定修補優先級

# ===== 高品質 Narrative（可接受）=====

攻擊路徑摘要：外部低權帳號 → 橫向移動 → 網域管理員

Step 1：初始存取（Finding #1：VPN 憑證噴洒成功）
  前提：外部可達 VPN 服務，帳號列舉可行
  攻擊者使用 crackmapexec 針對帳號列表執行密碼噴洒，
  成功以帳號 jsmith / Summer2024! 驗證進入 VPN。
  依據：見 Finding #1，截圖 evidence/screenshots/spray_success.png

  轉折點：若 MFA 已啟用，此步驟無法成立。

Step 2：橫向移動（Finding #2：SMB 憑證重用）
  前提：jsmith 密碼在內部 SMB 服務同樣有效
  進入 VPN 後，以相同憑證成功連線 10.10.10.20（財務工作站）。
  crackmapexec smb 10.10.10.20 -u jsmith -p 'Summer2024!'
  → STATUS_SUCCESS → 取得 SMB 存取
  依據：見 Finding #2，命令輸出 evidence/exploit/smb_jsmith.txt

  轉折點：若密碼政策禁止跨服務重用，此步驟無法成立。

Step 3：本機提權（Finding #3：sudo 設定不當）
  前提：jsmith 在財務工作站上為本機帳號，
        且 /etc/sudoers 中 jsmith 可 NOPASSWD 執行 python3
  sudo -n python3 -c "import pty;pty.spawn('/bin/bash')"
  → 取得 root shell
  依據：見 Finding #3，命令輸出 evidence/privesc/sudo_root.txt

  轉折點：若 sudoers 規則正確，此步驟無法成立。

Step 4：AD 提權（Finding #4：GPO 委派過寬）
  前提：財務工作站 root 可讀取 AD 系統管理帳號的快取憑證
  使用 secretsdump 傾倒快取 → 取得 IT-Admin Hash
  使用 Pass-the-Hash 以 IT-Admin 身份存取網域控制器
  依據：見 Finding #4，命令輸出 evidence/privesc/pthhash_dc.txt

最終影響：
  技術影響：攻擊者取得網域管理員級別存取，
             可完全控制 AD 環境、傾倒所有帳號 Hash、
             部署惡意 GPO。
  業務影響：所有網域內主機、使用者資料、財務系統
             均在攻擊者控制範圍，且難以確認入侵範圍。

路徑依賴說明：
  若以下任一條件成立，此攻擊鏈即斷裂：
  ① 啟用 VPN MFA（阻斷 Step 1）
  ② 修正 sudo 規則（阻斷 Step 3，最高效益）
  ③ 清除快取憑證（阻斷 Step 4）
```

## 攻擊敘事流程圖

```
初始存取
  ↓ 依賴 Finding #1
憑證濫用 / 橫向移動
  ↓ 依賴 Finding #2（前提：密碼重用）
本機提權
  ↓ 依賴 Finding #3（前提：sudo 設定）
AD / 系統提權
  ↓ 依賴 Finding #4（前提：快取憑證）
最終影響（技術 + 業務）
```

## 前提條件的書寫原則

```text
每一步都需明確標示前提（Preconditions）：

好的前提描述格式：
  「此步驟成立的必要條件為：
    (a) [環境條件]
    (b) [先前步驟的結果]
    (c) [特定設定存在]
  
  若以下條件不成立，此步驟無法執行：
    → [缺少哪個條件會阻斷此路徑]」

前提的作用：
  → 降低「誇大風險」的疑慮（限縮了成立條件）
  → 幫助防禦者判斷「改哪個前提最有效率」
  → 讓 narrative 嚴謹可辯護，不是推測性故事

常見前提類型：
  網路可達性：攻擊者必須在特定網段才能觸達目標
  已有憑證：此步驟依賴前一步取得的存取
  特定設定：目標必須有特定錯誤設定才成立
  使用者行為：需要使用者點擊 / 互動（降低可行性）
```

## 速查表

```text
Narrative 品質自問清單：

  □ 每一步都有對應 finding 編號（可回溯到具體證據）？
  □ 每一步都明確標示了前提條件？
  □ 是否說明了「轉折點」（什麼條件能阻斷此路徑）？
  □ 最終影響同時涵蓋技術與業務語言？
  □ 沒有任何推測性步驟（每步都有觀測依據）？

Narrative 標準輸出結構：
  Initial Access → 依賴 Finding #X（前提 Y）
  Lateral Movement → 依賴 Finding #X（前提 Y）
  Privilege Escalation → 依賴 Finding #X（前提 Y）
  Domain/System Impact → 技術 + 業務影響
  路徑依賴說明（切斷哪環最有效）
```

---

## 常見錯誤與排查

- 把推測性路徑寫成已發生事實 → Narrative 必須嚴格依附於已驗證的 finding，推測需明確標示為「假設」。
- 跳過關鍵步驟與前提 → 每一步的前提都要寫出來，否則讀者無法評估可行性。
- 技術鏈與業務影響斷裂 → 最後一步必須把技術影響翻譯成業務語言。
- 故事性太強、證據性太弱 → 每步至少引用一個 finding 編號或截圖，讓讀者知道這不是想像的。
