## 理論基礎

```text
Certificate Transparency (CT) 的本質：
  - TLS 憑證簽發事件的公開日誌系統
  - 目的：讓任何人都能稽核 CA 簽發記錄，防止惡意/誤簽發
  - 偵察價值：憑證的 CN/SAN 包含真實使用過的主機名稱

CT 相對於暴力猜測的優勢：
  - 名稱來自真實簽發事件，命名品質高
  - 能發現：停用服務、內部測試、品牌子站、API 入口、區域化站點
  - 歷史深度：舊憑證中的名稱可能仍指向真實資產

CT 的三個關鍵限制：
  1. 名稱出現在憑證 ≠ 目前仍可解析（必須 DNS 驗證）
  2. Wildcard 憑證（*.example.com）≠ 子名稱清單（方向線索，不是完整清單）
  3. CDN/WAF 代管憑證未必反映目標自有架構（第三方平台簽發）
```

## 查詢 CT Log

```bash
# 用 crt.sh API 查詢目標網域的憑證記錄
curl -s "https://crt.sh/?q=%25.example.com&output=json"
# q=%25.example.com → 查詢條件（%25 是 % 的 URL 編碼）
#   %25.example.com = *.example.com（所有子網域）
# output=json → 回傳 JSON 格式（預設是 HTML）
# -s → Silent mode（不顯示進度條）

# 萃取名稱欄位
curl -s "https://crt.sh/?q=%25.example.com&output=json" \
  | jq -r '.[].name_value'
# jq -r → 輸出 raw string（不含 JSON 引號）
# .[].name_value → 每筆憑證記錄的名稱欄位
# name_value 可能包含：
#   具體主機名稱：vpn.example.com
#   Wildcard 名稱：*.corp.example.com
#   多個 SAN（Subject Alternative Name）以換行分隔

# 完整清理流程
curl -s "https://crt.sh/?q=%25.example.com&output=json" \
  | jq -r '.[].name_value' \
  | sed 's/\*\.//g' \
  | tr '[:upper:]' '[:lower:]' \
  | sort -u > ct_candidates.txt
# sed 's/\*\.//g' → 移除 Wildcard 前綴（*.example.com → example.com）
# tr '[:upper:]' '[:lower:]' → 統一轉小寫（避免大小寫重複）
# sort -u → 排序並去重
# > ct_candidates.txt → 儲存候選名稱清單
```

## 過濾與分類

```bash
# 分離 Wildcard 名稱與具體名稱
curl -s "https://crt.sh/?q=%25.example.com&output=json" \
  | jq -r '.[].name_value' > raw_ct.txt

grep '^\*\.' raw_ct.txt > ct_wildcards.txt
# grep '^\*\.' → 只取以 *. 開頭的 Wildcard 名稱
# 這些只是方向線索（e.g., *.corp.example.com → corp 子網域存在）

grep -v '^\*\.' raw_ct.txt | sort -u > ct_specific.txt
# grep -v '^\*\.' → 排除 Wildcard，只留具體名稱
# 這些可直接做 DNS 驗證

# 從 Wildcard 萃取有價值的子網域層級線索
cat ct_wildcards.txt | sed 's/\*\.//' | sort -u
# 例如 *.corp.example.com → corp.example.com（確認 corp 子域存在）
# 用這些線索做更精準的暴力列舉

# 查詢特定憑證的詳細資訊
curl -s "https://crt.sh/?q=%25.example.com&output=json" \
  | jq '.[] | {id, name_value, not_before, not_after, issuer_ca_id}'
# 篩選出：憑證 ID、名稱、生效日期、過期日期、簽發 CA
# not_after → 確認憑證是否仍有效（過期不代表服務不在線）
```

## DNS 驗證 CT 候選

```bash
# 批次驗證 CT 具體名稱清單
dnsx -l ct_specific.txt -a -resp -silent -o ct_resolved.txt
# -l → 讀取候選名稱列表
# -a → 查 A 記錄（IPv4）
# -resp → 輸出含 IP 的完整結果
# -silent → 不顯示 banner
# 輸出：vpn.example.com [1.2.3.4]

# 快速驗證單一高價值候選
dig vpn.example.com +short
# +short → 只看 IP，確認是否可解析

curl -I https://vpn.example.com
# -I → 只取 HTTP Headers（HEAD 請求）
# 確認 Web 服務是否存在（最小互動驗證）
# 注意：這已是主動接觸目標，需確認在授權範圍內

# 對已解析結果追蹤 CNAME
for host in $(awk '{print $1}' ct_resolved.txt); do
  cname=$(dig "$host" cname +short)
  [ -n "$cname" ] && echo "$host → $cname"
done
# 識別指向 CDN/SaaS 的 CNAME（標記供應商，不直接掃描）
```

## 輸出分類標記

```bash
# 建立帶標記的輸出格式
# 格式：名稱 | 解析IP | 來源 | CNAME | 狀態 | 時間

# 對每個已解析主機附加來源標記
while read line; do
  host=$(echo "$line" | awk '{print $1}')
  ip=$(echo "$line" | grep -oP '\[\K[^\]]+')
  echo "$host | $ip | CT | - | live | $(date +%Y-%m-%d)"
done < ct_resolved.txt > ct_tagged.txt
# awk '{print $1}' → 主機名稱
# grep -oP '\[\K[^\]]+' → 從 [IP] 格式萃取 IP
# 附加：來源=CT、CNAME=-（待補）、狀態=live、時間

# 標記 CNAME 供應商類別
grep -i "cloudfront\|azurefd\|s3.amazonaws\|github.io\|fastly" ct_tagged.txt
# 識別高風險 Dangling CNAME 候選（指向可能被接管的第三方平台）
```

## 決策流程

```
Seed Domain
    ↓
查 crt.sh CT Log（curl + jq）
    ↓
分離名稱類型
  Wildcard（*.x.example.com）→ 萃取子域層級線索，用於後續暴力列舉
  具體名稱（sub.example.com）→ 進入 DNS 驗證
    ↓
DNS 驗證（dnsx -l）
  不可解析 → 標記為「歷史記錄」，降權保留
  可解析 → 追蹤 CNAME
    ↓
CNAME 分析
  指向第三方（CDN/SaaS）→ 標記供應商；檢查是否有 Dangling 風險
  指向自有 IP → 進入埠掃描 / httpx 清單
    ↓
歷史但目前不可解析的名稱
  保留清單 → 未來可重新驗證（服務可能恢復）
  不要與現役名稱等同看待
    ↓
整合進整體子網域列舉流程（第 9 章）
```

## 常見錯誤與排查

- 把歷史憑證名稱直接當成現役資產送進掃描 → CT 不代表服務在線，必須通過 DNS 驗證。
- 把 Wildcard 憑證展開成大量未驗證主機 → `*.corp.example.com` 只代表 corp 子域存在，不代表任意子名稱都有主機。
- 看到名稱在 CT 中就假設目標控制該服務 → CDN/WAF 可能為多個客戶統一簽發同一憑證，名稱不等於目標自有。
- 沒有與 DNS/HTTP 交叉驗證就報告資產 → CT 是偵察起點，不是終點。
