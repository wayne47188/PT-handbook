## 學習目標

- 理解 Infrastructure-based Enumeration 在外部資產發現中的定位。
- 能從 IP、ASN、DNS、服務與代管關係建立基礎設施視角。
- 分辨自有、代管、共享與第三方供應商資產。
- 把基礎設施資訊轉換為後續驗證與優先排序策略。
- 避免把網路層關聯直接當成完整業務歸屬。

## 理論基礎

```text
Infrastructure-based Enumeration 的核心問題：

不是「公司有哪些主機名稱」
而是「這個組織在網路與服務層面如何對外呈現」

四個視角：
  1. IP 與網段（自有 ASN / 雲端 / 代管）
  2. DNS 委派（權威 NS 指向誰 → 識別 DNS 供應商）
  3. 服務前端（CDN / WAF / LB / 雲端前端）
  4. 郵件與身份系統（MX / SPF / DKIM → 推測平台）

資產分類原則（最重要）：
  自有（On-Prem / 自有 ASN）→ 優先深入探測
  雲端（AWS/Azure/GCP 自控租戶）→ 確認租戶歸屬再探測
  代管（供應商管理，客戶只有內容控制）→ 標記，謹慎探測
  第三方（CDN/WAF/SaaS）→ 標記為前端，不直接掃供應商網段

錯誤判讀後果：
  把 CDN 網段（Cloudflare/Akamai）當成目標自有網段掃描
  → 超出授權範圍、誤判攻擊面
```

## WHOIS 查詢

```bash
# 從網域查 WHOIS 資訊
whois example.com
# 查詢內容：Registrar、Name Servers（DNS 委派）、Registrant Org、建立/到期日
# 重點欄位：
#   Name Server: ns1.example-dns.com  ← DNS 供應商線索
#   Registrant Organization: Example Corp  ← 組織關聯
# 注意：GDPR 後 Registrant 資訊常被遮蔽（Privacy Protected）

# 從 IP 查 WHOIS（找 IP 歸屬）
whois 203.0.113.10
# 查詢內容：NetName、NetRange、Organization、BGP Origin AS
# 重點判斷：
#   AMAZON-02 / MSFT / GOOGLE → 雲端平台（需確認租戶歸屬）
#   目標公司名稱 → 可能自有網段（仍需確認）
#   其他 ISP / DC 名稱 → 代管環境

# 從 ASN 查相關資訊
whois AS15169
# 查詢 ASN 持有者（AS15169 = Google）
# 用途：確認某段 IP 是哪家公司的 ASN

# 用 Cymru 查 IP 的 BGP 資訊（更精確）
whois -h whois.cymru.com " -v 203.0.113.10"
# 輸出：ASN | IP | BGP Prefix | CC | Registry | Allocated | AS Name
# 最快速確認 IP 的 ASN 與 BGP 路由歸屬
```

## ASN 與 BGP 視角

```bash
# 用 amass intel 從 ASN 找相關網域與網段
amass intel -asn 64500 -o asn_results.txt
# -asn → 輸入 ASN 號碼，amass 會找相關網域與子網域

# 找組織名稱關聯的 ASN（用 org 搜尋）
amass intel -org "Example Corp" -o org_asn.txt
# -org → 用組織名稱搜尋相關 ASN 與 IP 範圍

# 用 bgp.he.net 查詢（手動）
# https://bgp.he.net/search?search[search]=example+corp
# 查詢：ASN 清單、前綴（Prefix）清單、相關網域

# 從已知 IP 反推 ASN
curl -s "https://api.hackertarget.com/aslookup/?q=203.0.113.10"
# 輸出：ASN 號碼、網段、組織名稱
# 適合快速確認單一 IP 的 ASN 歸屬

# 從 ASN 取得所有相關 IP 前綴
curl -s "https://api.hackertarget.com/aslookup/?q=AS64500"
# 輸出：該 ASN 的所有 BGP 前綴
# 有助於建立目標自有 IP 範圍地圖
```

## DNS 委派分析

```bash
# 查詢權威 Name Server（識別 DNS 管理面）
dig ns example.com +short
# 輸出：ns1.cloudflare.com / ns1.awsdns.com / ns.example.com 等
# 判斷：DNS 是自管、Cloudflare、Route53、Azure DNS 還是其他供應商？

# 查詢 SOA（找主要 DNS 服務器與管理員）
dig soa example.com +short
# 輸出：ns1.example.com admin.example.com ...
# 管理員 email（第二欄點換@）有時能推測組織結構

# MX 記錄（郵件系統線索）
dig mx example.com +short
# 輸出：10 mail.example.com / 10 aspmx.l.google.com
# 判斷：Google Workspace / Microsoft 365 / 自建 Exchange / 其他
# MX 指向 google.com → G Suite / Google Workspace
# MX 指向 protection.outlook.com → Microsoft 365

# TXT 記錄（SPF/DKIM → 推測郵件平台與雲端服務）
dig txt example.com +short
# 找：v=spf1 include:... → 列出授權郵件傳送者（可能含雲端服務名稱）
# v=spf1 include:_spf.google.com → 使用 Google
# v=spf1 include:spf.protection.outlook.com → 使用 M365
# include:amazonses.com → 使用 AWS SES

# 查詢特定服務的 SRV 記錄（Skype/Teams/SIP等）
dig srv _sip._tls.example.com +short
dig srv _autodiscover._tcp.example.com +short
# _autodiscover → 用於 Exchange/M365 郵件客戶端自動配置
# 有回應 → 確認 M365 或 Exchange 環境存在
```

## 服務前端識別

```bash
# HTTP/HTTPS Header 分析（識別前端服務）
curl -I -k https://example.com
# 看 Server: 和 Via: Header
# Via: 1.1 cloudflare → Cloudflare CDN
# Server: AkamaiGHost → Akamai
# X-Cache: Hit from cloudfront → AWS CloudFront
# Server: nginx（但 IP 在 Cloudflare 範圍）→ CDN 前端，後端不明

# TLS 憑證分析（識別 CDN/WAF 或自有憑證）
echo | openssl s_client -connect example.com:443 -brief 2>/dev/null | \
  grep -E "CN|issuer|subject"
# 憑證 issuer 含 Cloudflare / DigiCert-Cloudflare → 明確 CDN
# 憑證 CN = *.example.com → 可能自有或 ACM/Let's Encrypt

# httpx 批次識別前端特徵
httpx -l hosts.txt -sc -title -server -tech-detect -silent
# 批次對多個主機做 Web 探測
# 技術指紋幫助辨識 CDN / WAF / 應用框架
```

## 資產分類決策流程

```
從已知主機名稱 / IP 出發
    ↓
WHOIS IP 查詢
  組織 = 目標公司名稱 → 可能自有（進入深度探測）
  組織 = AWS/Azure/GCP → 雲端（確認租戶歸屬）
  組織 = Cloudflare/Akamai → CDN 前端（標記，不掃供應商網段）
  組織 = ISP/DC → 代管（謹慎，確認授權範圍）
    ↓
DNS 委派分析
  NS 指向自有 → 自管 DNS（更多控制）
  NS 指向 Cloudflare/Route53 → 供應商 DNS（仍可查記錄）
    ↓
MX / TXT / SPF 分析
  識別郵件平台（Google/M365/Exchange）
  識別雲端服務（CDN/SaaS/API Gateway）
    ↓
HTTP Header / TLS 分析
  識別前端（CDN/WAF/LB）
  確認後端線索（Server Header / 錯誤頁 / 技術指紋）
    ↓
建立資產地圖（欄位：名稱/IP/ASN/供應商/類型/優先級）
```

## 速查表

```bash
# WHOIS
whois example.com                      # 網域 WHOIS
whois 203.0.113.10                     # IP WHOIS
whois -h whois.cymru.com " -v <IP>"    # BGP/ASN 快查

# DNS
dig ns example.com +short              # 權威 NS（DNS 供應商）
dig soa example.com +short             # SOA 管理資訊
dig mx example.com +short              # 郵件系統
dig txt example.com +short             # SPF/DKIM（雲端服務線索）

# ASN
amass intel -org "Example Corp"        # 從組織名找 ASN
amass intel -asn 64500                 # 從 ASN 找資產
curl -s "https://api.hackertarget.com/aslookup/?q=<IP>"  # IP→ASN

# 前端識別
curl -I -k https://example.com         # HTTP Header 分析
```

## 常見錯誤與排查

- 把雲端供應商或 CDN 網段誤當自有資產掃描 → 超出授權且浪費時間，先確認 IP 歸屬。
- 只看網域名稱不看服務與供應商關聯 → DNS/WHOIS/MX 分析才能建立完整視角。
- 沒區分網路歸屬（ASN）與業務歸屬（組織實際控制）→ 代管環境 ASN 屬 ISP，非目標。
- 沒有做資產分群直接開始探測 → 先分類再探測，節省時間且避免超出範圍。
