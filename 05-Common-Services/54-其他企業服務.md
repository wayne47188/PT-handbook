## 學習目標

- 建立面對未知或次要企業服務時的通用分析框架。
- 能從 banner、協定、埠、命名與角色推回服務性質。
- 知道如何低風險地驗證不熟悉服務的存在與基本能力。
- 將零散服務發現整理成後續研究與優先排序方向。

---

## 理論基礎

```text
企業環境常見非主流但高價值的服務類型：

管理面：
  - IPMI / iDRAC（623/udp）：伺服器遠端管理，IPMI 2.0 有 hash 洩漏漏洞
  - Jenkins / GitLab（8080/8443）：CI/CD 平台，可能有 RCE 路徑
  - Zabbix / Nagios（10050/tcp）：監控系統，代理常有 RCE 能力

應用平台：
  - ColdFusion（8500/tcp）→ 見 54B
  - Tomcat（8080/tcp）→ 見 54A
  - JBoss / WildFly（8080/8443）：Java EE，/jmx-console 是高價值入口

備份與儲存：
  - Veeam（9392/tcp）、Bacula（9101/tcp）：備份伺服器常含大量憑證
  - NetBackup（13720/tcp）

內部代理與閘道：
  - SOCKS / Squid（3128/tcp）：可能作為跳板進入內部網段
  - HAProxy / Nginx（80/443）：反向代理，路由設定錯誤常見

識別邏輯：
  高權限管理面 > 含憑證的備份服務 > CI/CD 平台 > 監控代理 > 基礎設施閘道
```

## 方法一：服務發現與辨識

```bash
# 全埠掃描（先快速）
nmap -sV --open -T4 TARGET_IP
# --open → 只顯示開放埠
# -T4 → 加快掃描速度
# 看 service / version 欄位

# 詳細服務辨識（確認候選目標）
nmap -sV --reason -p PORT TARGET_IP
# --reason → 顯示 nmap 判斷該服務的依據（syn-ack / banner 等）

# Banner 抓取（通用）
nc -nv TARGET_IP PORT
# 直接看服務回應，找供應商名稱 / 版本字串

# HTTP 類服務快速辨識
curl -s -I http://TARGET_IP:PORT
# -I → 只看 header（Server / X-Powered-By / Location）

# HTTPS 類服務（含憑證資訊）
curl -sk -I https://TARGET_IP:PORT
# -k → 忽略憑證錯誤
# 看 CN / SAN 欄位 → 洩漏主機名稱與服務名稱

# 憑證欄位詳細查看
openssl s_client -connect TARGET_IP:PORT </dev/null 2>/dev/null | openssl x509 -noout -subject -issuer -san
# subject / issuer → 供應商或組織
# san → Subject Alternative Names，可能包含多個服務 FQDN
```

## 方法二：角色分類與風險排序

```bash
# 確認是否為 IPMI / iDRAC（伺服器遠端管理）
nmap -sU -p 623 TARGET_IP
# UDP 623 → IPMI（Intelligent Platform Management Interface）

# Metasploit 取得 IPMI 2.0 RAKP hash
# use auxiliary/scanner/ipmi/ipmi_2_0_rakp_hmac_sha1
# set RHOSTS TARGET_IP
# run
# → 可離線破解伺服器的 BMC 密碼（常為預設 admin/admin）

# 確認是否為 Jenkins
curl -s http://TARGET_IP:8080/api/json
# 回傳 JSON → Jenkins API 無需認證，可列出 job / build 資訊

# 確認是否為 Zabbix Agent（監控代理，可能允許遠端命令）
nmap -p 10050 TARGET_IP
echo "system.run[id]" | nc TARGET_IP 10050
# 若回傳 uid=... → Zabbix agent 允許 system.run（可 RCE）

# 確認是否為 Squid Proxy（可能做跳板）
curl -x http://TARGET_IP:3128 http://internal.target.com
# -x → 透過代理發請求
# 若回傳內部頁面 → 可用 Squid 當跳板存取內網
```

## 方法三：Web 管理介面快速枚舉

```bash
# 常見高價值路徑（對任何 HTTP 服務都值得試）
for PATH in /admin /manager /console /jmx-console /web-console \
  /login /dashboard /api /swagger /actuator /health; do
  curl -s -o /dev/null -w "$PATH → %{http_code}\n" http://TARGET_IP:PORT$PATH
done
# 200 → 存在且可存取
# 301/302 → 重定向（追蹤 Location）
# 401/403 → 存在但需認證（仍是高價值）

# Gobuster 找隱藏路徑
gobuster dir -u http://TARGET_IP:PORT -w /usr/share/seclists/Discovery/Web-Content/common.txt -t 30 -x jsp,php,html
# -x → 額外副檔名（依服務類型調整）

# 預設憑證嘗試（依服務）
# Jenkins：admin:admin、admin:password
# Zabbix：Admin:zabbix
# JBoss：admin:admin
# IPMI：admin:admin、ADMIN:ADMIN
curl -s -u admin:admin http://TARGET_IP:PORT/api/
```

## 方法四：確認後的低風險驗證

```bash
# 若為備份服務（Veeam / Bacula）→ 確認版本與暴露程度
nmap -sV -p 9392 TARGET_IP    # Veeam Enterprise Manager
nmap -sV -p 9101-9103 TARGET_IP  # Bacula

# 若為 JBoss（Java EE Application Server）
curl -s http://TARGET_IP:8080/jmx-console/
# JBoss 4.x：/jmx-console 無需認證 → 可部署 WAR → RCE
# JBoss 5+：通常有認證但仍是高價值

curl -s http://TARGET_IP:8080/web-console/ServerInfo.jsp
# 洩漏 JBoss 版本與 OS 資訊

# 若為監控系統（Nagios）
curl -s http://TARGET_IP/nagios/
# 預設認證 nagiosadmin:nagios（常見未改）

# 若為 CI/CD（GitLab）
curl -s http://TARGET_IP/users/sign_in
# 找 GitLab 版本（在頁腳或 /api/v4/version）
curl -s http://TARGET_IP/api/v4/version
# 若無需認證 → 公開 API，可列出 projects / users / repos
```

## 決策流程

```
nmap -sV 發現未知服務
    ↓
判斷協定類型：
  HTTP → curl -I / gobuster / 預設憑證
  TCP banner → nc 取得回應
  UDP → nmap -sU + 對應 NSE
    ↓
判斷服務角色：
  管理面（IPMI/Jenkins/JBoss）→ 優先測試，高 RCE 潛力
  備份服務（Veeam/Bacula）→ 記錄，常含憑證 dump 路徑
  監控代理（Zabbix/Nagios）→ 確認 system.run 或預設憑證
  代理閘道（Squid）→ 測試是否能當跳板
    ↓
找到版本 → 查 CVE / exploit-db
找到管理介面 → 試預設憑證 → 若成功進入下一階段
```

## 常見錯誤與排查

- 因為不熟悉就直接忽略 — 冷門服務往往是最高價值入口。
- 只看 HTTP，忽略 UDP 服務（IPMI 就是 UDP）。
- 看到服務就急著上 exploit，應先完整確認版本與暴露程度。
- 不把服務角色放回整體架構：備份伺服器/CI-CD/監控系統常直連大量主機。
