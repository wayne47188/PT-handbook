## 理論基礎

```text
Pivoting 流量模型：

Attacker ──SSH/隧道──> Pivot Host ──內網──> Internal Target

關鍵問題：
  1. 誰能連到誰？（防火牆方向）
  2. DNS 在哪一端解析？
  3. 回程路徑是否存在？
  4. 建立的是哪種通道？

三種通道類型：
  Local Port Forward：把本地單一埠轉到遠端服務
    攻擊機 localhost:1433 → Pivot → 內網 DB:1433
    適合：確定的單一服務存取

  Dynamic / SOCKS Proxy：SOCKS5 proxy，多目標
    攻擊機 SOCKS 1080 → Pivot → 任意內網目標
    適合：要用多種工具掃描/存取內網

  Full Route / VPN-like：在攻擊機添加路由，讓整段網段可達
    ip route add 172.16.0.0/24 via Pivot_TUN_IP
    適合：需要真正 IP 可達（Ligolo-ng、Metasploit route）

常見誤解：
  做了 SOCKS proxy 不等於整段網段可 ping/scan（SOCKS 是 TCP 代理）
  做了 SSH local forward 不等於其他工具也能走那條通道
```

## 方法一：在 Pivot 主機上收集網路資訊

```bash
# 確認所有網路介面（Linux）
ip addr show
# 或
ifconfig
# 找多個 inet → 多個介面 → 可能連接多個網段
# 例：eth0=192.168.1.100（外部）/ eth1=172.16.0.10（內部）

# 確認路由表（了解 pivot 主機能看到哪些網段）
ip route show
# 或
route -n
# 輸出範例：
# 172.16.0.0/24 dev eth1 → 直接連接，不需要閘道
# 0.0.0.0/0 via 192.168.1.1 → 預設閘道

# ARP 表（確認 pivot 主機最近與哪些 IP 通訊）
arp -a
# 或
ip neigh
# 輸出：172.16.0.5 ether MAC → 這個 IP 存在且最近通訊過

# 確認監聽服務（找到 pivot 主機自身暴露的服務）
ss -tlnp
# 或
netstat -tlnp
# -t → TCP、-l → listening、-n → 數字顯示、-p → 顯示 PID

# Windows 上的等效命令
ipconfig /all
route print
arp -a
netstat -ano
```

## 方法二：從 Pivot 掃描內網（確認可達服務）

```bash
# 在 Pivot 主機上用 ping 掃描內網（bash loop）
for i in $(seq 1 254); do
  ping -c 1 -W 1 172.16.0.$i 2>/dev/null | grep "bytes from" && echo "172.16.0.$i is UP"
done
# -c 1 → 只送一個 ping
# -W 1 → 等待 1 秒
# 找出活著的主機

# 在 Pivot 上用 nmap 掃描內網（有 nmap 的情況）
nmap -sn 172.16.0.0/24
# -sn → ping scan（只確認主機是否存活，不掃埠）

# 有工具的情況：用 nmap 掃描特定主機
nmap -sT -p 22,80,443,3389,445,1433 172.16.0.5
# -sT → TCP connect scan（不需要 root，適合 pivot 主機上執行）

# Windows Pivot 主機
for /L %i in (1,1,254) do @ping -n 1 -w 100 172.16.0.%i | findstr "Reply" && echo 172.16.0.%i UP
```

## 方法三：在攻擊機上添加路由（Full-Route 模式）

```bash
# 當使用 Ligolo-ng 或 Metasploit route 後，需要在攻擊機上添加路由

# Linux 添加路由（讓攻擊機認識 172.16.0.0/24 要走哪個介面）
sudo ip route add 172.16.0.0/24 via TUNNEL_INTERFACE_IP
# 或
sudo ip route add 172.16.0.0/24 dev ligolo
# ligolo → Ligolo-ng 建立的虛擬介面

# 確認路由已生效
ip route show | grep 172.16.0
# 看到目標網段 → 攻擊機現在知道要把那段流量送哪

# 驗證路由是否可達（直接 ping 內網 IP）
ping 172.16.0.5
# 有回應 → full-route 成功，整段網段可達

# 測試服務可達性
curl http://172.16.0.5/
nmap -sT -p 80,443,22 172.16.0.5
# 不需要 proxychains → 直接可達
```

## 方法四：判斷流量模型

```bash
# 確認攻擊機現在透過哪條路徑到達目標
traceroute 172.16.0.5
# 或 Windows
tracert 172.16.0.5
# 看到跳數：攻擊機 → Pivot → 內網目標 → 確認路徑正確

# 確認 SOCKS proxy 是否可用（用 curl 測試）
curl --proxy socks5h://127.0.0.1:1080 http://172.16.0.5/
# --proxy socks5h:// → 透過 SOCKS5 代理（h = DNS 也透過代理解析）
# 有回應 → SOCKS proxy 正常運作

# 確認 local port forward 是否可用
curl http://localhost:8080/
# 若有做 SSH -L 8080:172.16.0.5:80 → 這個應回傳內網服務的頁面

# DNS 解析位置確認
# 若用 socks5:// → DNS 在攻擊機解析（可能失敗）
# 若用 socks5h:// → DNS 在 proxy 端解析（正確）
curl --proxy socks5h://127.0.0.1:1080 http://internal-hostname/
# -h 結尾 → hostname 在遠端解析
```

## 決策流程

```
進入 Pivot 主機
    ↓
ip addr show / ip route show → 找出內部網段
ARP / ping sweep → 找出活著的主機
    ↓
需要存取：
  單一固定服務？
    → SSH Local Port Forward（-L LOCAL:TARGET:REMOTE）
  多個服務、多個目標？
    → SOCKS Proxy（SSH -D / Chisel / Ligolo-ng）
    → proxychains4 包覆工具
  需要真正 IP 可達（nmap -sS、ping 等）？
    → Full Route（Ligolo-ng + ip route add）
```

## 速查表

```bash
# Pivot 主機網路資訊收集
ip addr show
ip route show
arp -a
ss -tlnp

# 內網 ping sweep
for i in $(seq 1 254); do ping -c1 -W1 172.16.0.$i 2>/dev/null | grep "bytes from"; done

# 攻擊機添加路由（full-route 後）
sudo ip route add 172.16.0.0/24 dev ligolo

# 驗證通路
ping 172.16.0.5                                           # full-route
curl --proxy socks5h://127.0.0.1:1080 http://172.16.0.5  # SOCKS
curl http://localhost:LOCAL_PORT/                          # local forward
```

---

## 常見錯誤與排查

- SOCKS proxy 建好，但 nmap -sS 掃不到 → SOCKS 只支援 TCP connect，不支援 raw socket；改用 `-sT` 或 full-route。
- local port forward 成功，但其他工具還是連不到內網 → local forward 只開了一個埠，其他工具要另外 forward 或改用 SOCKS。
- DNS 解析失敗（連到外網 IP）→ 用 `socks5h://` 而非 `socks5://`；或在 proxychains.conf 設 `proxy_dns`。
- 添加路由後還是 ping 不通 → 確認 Ligolo-ng/隧道介面是否已啟動；確認 pivot 主機的 IP 轉發是否開啟（`sysctl net.ipv4.ip_forward`）。
